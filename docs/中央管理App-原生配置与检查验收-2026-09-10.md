# 中央管理 App：原生配置与基础检查验收

日期：2026-09-10。承接用户“继续”要求，在现有 `apps/central` 中将 Windows 本机预备配置和基础环境检查接到 UI。本批未完成实际服务启停，P1 尚未完成。

## 可以使用的功能

- 首次配置第三步增加“保存本机配置”：证书/运行包标识与并发限制一并保存；页面草稿仍保留独立按钮。
- 原生配置读取后恢复目录和连接地址，显示当前版本。保存前再次执行原生严格校验；冲突后读取最新版本，保留用户当前输入以便核对。
- 保存超时或结果不明时保留原 requestId 和请求内容，用户可核对上次结果。幂等重送成功后再读取最新配置，避免旧 receipt 把界面显示退回旧版本。
- 概览和“设置与诊断”提供启动前检查。结果带配置版本、时间与六项状态；未知数值保持未知，服务启动按钮继续禁用。

## 原生实现与边界

`apps/central/src-tauri/src/config.rs` 提供 `central_config_read`、`central_config_validate`、`central_config_save`、`central_runtime_inspect`，由 `main.rs` 注册 Tauri IPC。沿用现有管理契约字段，拒绝未知字段，错误只返回稳定 code、recoverable 与 diagnosticId，不将异常文本或凭据返回页面。

配置存储固定为当前应用数据目录的 `config/central-config.json`，独占锁为同目录 `central.lock`。中央数据默认改为 `central-data` 子目录，与配置和 WebView 数据分开。保存不创建用户指定的数据目录，不初始化或覆盖用户库。

配置与保存 receipt 在同一个版本化 JSON 中原子提交，支持跨重启去重和期望版本检查。Windows 检查已有路径、拒绝既有 reparse/junction 与文件硬链接；保留祖先目录句柄及跨进程锁。保存目录允许写入共享但禁止删除共享，临时文件独占访问，通过已检查目录句柄进行原子重命名，写入失败保留旧版本。

这是 Windows **非秘密预备配置**存储，不是凭据隔离资格证明，也不承诺隔离同用户恶意修改末级目录 reparse 属性。未来接入秘密、受管进程和启动前检查时仍需相应所有者/ACL/受信资源检查。本轮 macOS 原生读写返回 `RUNTIME_PLATFORM_MISMATCH`，因为同等的目录句柄锚定保护尚未完成；不会静默退回不安全路径。macOS 页面草稿不受影响。

当前账本上限为 1024 条保存 receipt、整个文件 4 MiB，先达到者生效。上限返回不可重试的 `CONFIG_STORAGE_FULL`，已保存配置可继续读取；后续需有版本化保留/迁移策略，不能把清空文件作为恢复建议。

## 检查项目

| 项目 | 本轮实现 |
|---|---|
| 操作系统 | 实际识别 Windows/macOS；不代表运行包兼容性通过 |
| 地址与端口 | 尝试绑定已保存监听地址，立即释放；失败提示地址、占用或权限问题 |
| 数据目录 | 检查存在状态、既有父路径链接与目录是否为空；已有内容要求兼容检查或迁移 |
| 运行包 | 受信目录与哈希验证未接入，返回未检查 |
| 证书 | 存储和有效性验证未接入，返回未检查 |
| 隔离 | 正式 Worker 生命周期未接通，返回未检查 |

数据目录的所有者、ACL、空间和写入权限尚未完整验证，因此即使目录为空也不把该项报为全部通过。保存标识不代表资源已经安装，不会读取登录、调用模型或连接正式网关。
