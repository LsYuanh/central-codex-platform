# 按用户 Worker 管理：P5 第二批

用户确认范围：每用户独立中央 Worker/运行目录/会话路由、并发限制、崩溃恢复、持久化审计，以及 4529 双用户并发与故障验收。本批实现与下述验收已完成，测试服务已停止，未发布。

## 实现

平台认证模式下，网关按服务端验证的 userId 懒启动 Worker；目录名称取 userId 的 SHA-256，每用户独立 `home`/`runtime`，分别设置 `CODEX_HOME`/`CODEX_REMOTE_WORKER_DIR`。请求、异步工具、审批响应及事件绑定实际 Worker 实例。Thread 的平台归属仍是权威校验，Worker 返回其他用户 Thread ID 时拒绝，既有归属不得覆盖。

Worker 退出只使所属用户任务进入需核对状态，取消该用户关联的设备命令和审批；仍存活的其他 Worker 继续运行。请求可以在短暂退避后重新创建 Worker，重用原有用户目录；失败中的 Turn、文件修改和命令不自动重发。旧 Worker 的缓冲消息丢弃，审批使用随机独立 ID，旧审批响应不能批准重启后的新操作。

默认最多 8 个存活 Worker、每用户 2 个活动 Turn、全局 8 个活动 Turn、每 Worker 32 个待返回 RPC。超限明确拒绝，不进入无限队列；已知终态释放名额，超时结果未知时保守占位。匹配已知 Turn ID 的明确终态历史也可释放名额；完全未知的提交须进一步核对或由管理员停止 Worker。无活动 Turn/RPC 的 Worker 默认空闲 5 分钟回收，正常空闲回收不向 UI 报崩溃。

配额按本次提交的预约对象和 Turn ID 匹配：旧 Turn 的迟到完成事件不能释放新提交名额；完成事件早于启动响应时，保留名额直到响应确认同一 Turn ID。

## 配置

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `PLATFORM_WORKER_ROOT` | 网关状态目录下 `workers` | 每用户中央运行数据根目录 |
| `PLATFORM_MAX_WORKERS` | 8 | 活跃/正在退出的 Worker 上限 |
| `PLATFORM_USER_TURNS` | 2 | 每用户活动或结果未知 Turn 上限 |
| `PLATFORM_TOTAL_TURNS` | 8 | 全局活动或结果未知 Turn 上限 |
| `PLATFORM_WORKER_REQUESTS` | 32 | 每 Worker 待返回 RPC 上限 |
| `PLATFORM_WORKER_IDLE_MS` | 300000 | 无活动任务后的空闲回收时间 |
| `PLATFORM_WORKER_RESTART_MS` | 1000 | 退出后的最短重新启动等待时间 |
| `PLATFORM_AUDIT_DIR` | 网关状态目录下 `audit` | 持久审计目录，认证模式默认开启 |

审计仅保存操作类型、时间、状态、用户/设备/请求标识和错误码，不保存对话、文件正文、密码或令牌。认证 API、设备连接/执行/审批、Worker 启停、配额拒绝都进入审计。管理员认证后可 GET `/audit` 查看最近 1000 项，GET `/workers` 查看 Worker 的 PID、就绪、RPC/Turn 数；普通用户无权读取。日志按大小分段，历史分段保留在中央运行数据目录；本轮不自动删除历史审计，也未实现保留期限管理。

## 兼容与边界

- 原共享运行目录中的历史不能仅靠更换 `CODEX_HOME` 迁移。认证模式发现既有 Thread 元数据而无 `workerLayout=per-user/v1` 时以 `WORKER_LAYOUT_MIGRATION_REQUIRED` 拒绝启动，保留旧数据；测试使用全新的 QA 状态文件。正式历史迁移需单独做可恢复迁移方案。
- 明文局域网旧模式保留现有单 Worker 行为，正式 4510 尚未更新。
- 独立进程/目录是本批管理边界，不能代替操作系统权限隔离。本批未完成正式模型凭据管理、完整 mTLS、安装升级与发布。
- 本轮 QA 沿用已有中央只读模型登录链接并禁止刷新/撤销，没有把模型凭据复制到客户端；每用户配置与链接由开发专用 QA 引导准备，产品 Worker Manager 不复制或自动共享模型凭据。
- 审计按单网关写入设计，不是分布式日志服务；异常存储停止新执行，需修复后重启。审计中有失败记录并不证明客户端未知操作从未发生，仍须核对实际文件/历史。
