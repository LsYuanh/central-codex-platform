# 中央模型凭据过期恢复

日期：2026-09-20。用户授权直接在中央端解决客户端 `MODEL_CREDENTIAL_EXPIRED` 报错。

## 原因

- 正式中央管理端导入的 5 份账号记录均为同一账号的旧 access token，均在北京时间 2026-09-20 11:27:31 到期。
- 中央机原始 `~/.codex/auth.json` 已于当天 11:23:32 更新，新的 access token 到期时间为北京时间 2026-09-30 11:23:32。
- 中央管理端导入的是独立凭据快照，运行中网关从原生启动管道接收该快照并保存在内存，不会跟随原登录更新，也没有自动刷新功能。
- 修复前正式 `/model-access` 返回 `expired / MODEL_CREDENTIAL_EXPIRED`；`/workers` 返回空列表，没有活动任务。

## 本次处理

1. 通过已有 SSH 运维连接在中央机本地检查凭据元数据，确认新旧凭据属于同一账号；原始 token、刷新令牌和管理员密码均未输出或下载。
2. 正常退出已安装中央管理应用，并确认原应用及所属服务进程退出。
3. 在现有 macOS 私有凭据库按既有 Bundle 格式新增一条 0600 账号记录，仅包含 schemaVersion、importedAt、accessToken、accountId；保留所有旧记录。操作期间中央应用已退出，写入后执行 fsync 并回读验证。
4. 使用原有已安装中央应用和原运行包，通过既有 `--start-account` 启动入口加载新记录；更新现有运维 deployment/running 元数据，并在中央机保存修改前副本。
5. 核对正式 `/model-access` 恢复为 `ready`，中央配置文件字节保持一致。没有修改源登录、应用代码、运行包、用户、配对、证书或版本清单。
