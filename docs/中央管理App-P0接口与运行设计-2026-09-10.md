# 中央管理 App P0：接口与运行设计

日期：2026-09-10。用户确认的本批范围为 Windows 中央运行验证与管理接口设计。
本文对应现有 `spikes/local-dev` 工程；新增代码是契约与验证工具，尚未提供中央 App、管理监听端口或 Windows 生产 Worker。

## 1. 角色、身份与数据

- 工作客户端保留 `apps/desktop`，中央 App 后续新增 `apps/central`，应用标识采用 `com.yuanzhou.central`；RC 再增加独立后缀。
- 中央 App 管理安装所在机器；客户端的文件、Git、命令继续由目标 Local Agent 执行。
- React 只通过 Tauri IPC 获取公开状态和提交受限操作。原生层持有管理会话、受保护配置、服务进程及模型秘密；不得向 React 提供任意 shell、任意 HTTP 转发或环境变量注入。
- 第一版沿用管理员密码登录及管理员会话鉴权，普通工作用户使用配对专用身份。设备令牌不拥有管理权限。
- 管理会话保存在原生内存，续期由原生层处理。配对码仍绑定发码会话；登出时使未消费码失效，并明确提示。不能调用完发码接口就自动登出。
- 首次初始化只允许新的空数据目录；已有身份库进入兼容检查或显式迁移流程。安装和启动均不得覆盖用户库。
- 稳定配置目录、中央数据目录、只读运行包目录分离。模型秘密及中央管理员状态放在 Worker 目录外；工作客户端、中央 App、QA 配置互不复用。

Windows 受保护存储需复用 DPAPI/ACL 能力，但中央模型代理当前仍读取 JSON 文件：不能直接把加密文件塞入原读取路径。P1 需实现原生解密到受限 IPC 的读取适配，或由原生模型代理持有秘密；不得用长期明文中间文件衔接。Mac 私有权限文件保持明确的“未加密”语义。

## 2. 配置契约

P0 TypeScript 定义及纯校验位于：

`spikes/local-dev/services/test-gateway/src/central-management-contract.ts`

后续出现两个实际消费者后，再抽取为管理专用共享包；不混入 AgentRPC 设备执行协议。

```json
{
  "schemaVersion": 1,
  "revision": 0,
  "dataDirectory": "C:\\YuanZhou Central\\data",
  "listen": { "host": "0.0.0.0", "port": 4510 },
  "clientUrl": "wss://central.example.internal:4510/ws",
  "tls": { "certificateId": "local-ca-1" },
  "runtimePackageId": "windows-x64-qualified-release",
  "limits": { "maxWorkers": 8, "perUserTurns": 2, "totalTurns": 8 },
  "shutdown": { "graceMs": 10000, "forceMs": 5000 }
}
```

示例不是可直接使用的实际中央地址或已存在运行包。

- 使用 `expectedRevision` 防止两个窗口或迟到响应覆盖新配置。成功保存后递增 revision，返回已持久化值。
- 第一版用户可配置端口为 1024–65535，避免为了默认 443 引入常驻提权。暂不支持反向代理，客户端地址端口必须与监听端口一致。
- `listen.host` 是本机 IP 或通配监听 IP；`clientUrl` 必须是客户端可达的 WSS `/ws` 地址，不能使用 localhost、回环、通配地址、URL 凭据、查询参数或片段。
- 路径纯校验拒绝相对路径、磁盘根、UNC、设备路径、ADS 与 `..`；Windows 额外拒绝保留设备名及目录段尾随点/空格，中文和普通空格保留。文件系统规范化、卷类型、父目录 reparse/符号链接、所有者、ACL、磁盘空间必须另由原生层检查。Windows 名称规则见 [Microsoft 文件命名文档](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)。
- TLS 私钥、模型秘密、管理员密码、运行包绝对可执行路径不进入该 DTO；证书/包 ID 由原生受信目录解析，不能成为任意路径入口。
- 保存采用同目录临时文件、持久化、原子替换。写失败保留旧配置。运行中改监听地址、数据目录、运行包或 TLS 必须明确停机影响；P1 建议只允许停止状态应用这类变更。

**P0 的纯校验不能代替原生权限、TLS、DNS 和运行包检查。** 当前代码未实现持久化、账号初始化或管理命令处理器。

输入按 IPC 的 JSON 数据对象设计；所有配置字段均为必填自有数据字段，拒绝额外字段、继承字段和访问器。通过后返回与调用方对象脱离的副本。URL 拒绝控制字符、空白和反斜杠，避免 URL 解析器静默修正后与保存值不一致。该 TypeScript 校验器不是原生鉴权边界，P1 原生处理器必须独立验证请求。

## 3. 管理命令与边界

以下名称是待接入 Tauri 的逻辑操作，当前没有新增网络 API。

| 操作 | 输入 | 返回/语义 |
|---|---|---|
| `central.config.read` | 空对象 | 公开配置、revision、初始化状态 |
| `central.config.validate` | 配置 | 有界字段错误；不回显秘密或原始异常 |
| `central.config.save` | requestId、expectedRevision、配置 | 保存后的配置，或明确冲突/存储错误 |
| `central.runtime.inspect` | 空对象 | 包、系统、端口、TLS、目录和隔离检查；不启动推理 |
| `central.runtime.start` | requestId、expectedRevision | operation（含 ID）；最终结果通过状态/操作查询确认 |
| `central.runtime.stop` | requestId、expectedInstanceId | operation（含 ID）；只停止本 App 创建的服务 |
| `central.operation.read` | operationId | accepted/running/succeeded/failed/unknown |
| `central.status.read` | 空对象 | 当前实例的一致状态快照 |

输入和返回 DTO 已在契约中成对声明，统一结果为 `ok + value` 或 `ok + failure`。失败只返回稳定错误码、是否可恢复及原生诊断 ID，不返回异常文本。配置校验的字段问题位于成功调用返回的 `ConfigValidation` 内；鉴权或内部处理失败使用外层 failure。未初始化的配置读取返回 `config: null`。

以下是 **P1 处理器必须落实、当前尚无执行代码** 的语义：

- 保存时 `config.revision`、`expectedRevision` 必须等于当前持久化版本；服务端递增版本并返回新配置，溢出时拒绝保存。对初始化状态和数据目录兼容性的判断由原生层负责，不能从 DTO 的 revision 推断。
- 写操作按管理主体与 `requestId` 去重；同 ID 同参数返回原结果，不同参数明确拒绝。副作用发生前记录操作身份，原生进程重启后先恢复/核对未完成操作，不能因为内存去重表丢失再执行一次。
- `central.operation.read` 查询不到时返回 `OPERATION_NOT_FOUND`，不等于从未执行；超时或记录缺失后核对受管进程与配置，再决定恢复。`recoverable` 表示可提供恢复流程，不是授权自动重试。
- 预检返回配置 revision、检查时间与包/系统/端口/TLS/目录/隔离六项状态。未执行项明确 `not-checked`，不能因为列表为空或仅部分通过而准许启动。启动再次检查当前配置和环境，防止使用过期预检。
- 所有 `*At` 均为 Unix epoch 毫秒。状态事件必须由可信原生通道完成运行时结构校验；`acceptStatusEvent` 只是实例和序号的排序辅助函数，不承担反序列化或完整快照验证。

原生管理层与网关建议采用受管子进程的独立匿名管道控制通道：与 Worker stdio 分开，只允许固定管理操作；启动时建立一次性随机能力，要求握手、请求 ID 和超时。网关侧仍需验证独立管理主体与允许操作，不能把“来自本机/管道”直接等同于管理员。若复用现有 HTTPS 管理接口，原生层内部使用管理员会话，不将 bearer 交给 React；不增设无鉴权 loopback 后门。

现有管理员接口继续复用。P2 扩展需求：

| 缺口 | 实施约束 |
|---|---|
| 配对专用用户 | 用户记录增加版本化身份类型；管理员 password 身份与 pairing-only 身份明确分开；后者不能密码登录。不能生成占位密码 |
| 重新启用用户 | 单独接口；只恢复用户可用性，不复活已撤销设备/旧会话，不重放旧任务 |
| 设备在线状态 | 设备公开记录与当前 Agent 连接合并，区分未连接、就绪、失联和撤销 |
| 模型管理 | 新增管理员 provider/用户绑定操作；当前 `/model-access` 仅表示调用者状态 |
| 活动任务 | 受认证管理员快照，包含所属用户、Thread/Turn、阶段及用时；`/workers` 的计数不是完整任务列表 |
| 审计查询 | 持久分段有界分页和保留策略；当前 `/audit` 最多是近期 1000 项缓存，不能当完整历史 |

P0 不修改上述业务接口和现有认证默认值。

## 4. 运行状态与停止协议

服务状态为 `unconfigured → stopped → starting → running → stopping → stopped`，启动/运行/停止异常进入 `failed`。
原生操作超时后先标记 `unknown` 并核对进程、端口及实例，不自动重发。已失败启动但仍有进程时不能显示“已停止”。

快照带 `instanceId + sequence + observedAt`。同实例仅接受递增 sequence；其他实例的事件不能覆盖当前状态，必须重新读取可信快照。网关、模型代理、Worker 独立显示状态；没有活跃用户、Worker 数为 0 是 idle，不自动标为模型失败。启动预检成功也不等于真实模型调用成功。

停止按以下步骤执行：

1. 原生层校验受管进程身份，包括持有的进程句柄/启动时间/程序路径/运行包哈希/实例握手，拒绝仅凭 PID 或端口接管。
2. 网关进入 draining，停止接收新 Turn/新连接；已有中断与结果上报仍可处理。
3. 向活动 Turn 发中断、取消审批和设备命令，等待有界终态；没有收到客户端退出证据时记作 unknown，不能伪报命令已退出。
4. 关闭 Worker、模型代理和连接，等待各进程实际退出、端口释放及必要状态写入。
5. 到期后只终止受管进程树；仍无法确认时返回 `SHUTDOWN_INCOMPLETE`，阻止重叠启动。

Windows 使用 Job Object 处理父进程异常退出后的回收，并在恢复线程前加入 Job，不能把 Job 当文件或网络沙箱。
当前网关 SIGINT/SIGTERM 路径直接 `process.exit(0)`，尚未实现上述有界停止确认；P1 应抽取单一 shutdown 实现并验证。

首次页面建议关闭窗口和显式退出均触发受管服务停止；有活动任务时展示影响和退出进度。若未来需要关窗后常驻，作为单独产品决策，不隐式安装系统服务。

## 5. Windows 隔离决策与 P0 门槛

现有 `worker-isolation.ts` 的 macOS Seatbelt 实现保持不变。Windows 验证通过前继续返回 `WORKER_ISOLATION_UNSUPPORTED`，不启用协议 fixture、无沙箱或普通未打补丁 Codex 的替代运行路径。

候选原型：每用户独立 AppContainer SID、只向本用户运行目录授权、无网络 capabilities、限制子进程、显式环境白名单、受管 Job。验证必须使用真实 OS 调用探针，不只检查启动参数。

必须区分以下证明：

- 探针二进制能编译，不证明 AppContainer 能运行。
- AppContainer 能启动，不证明所有文件、网络与跨进程边界成立。
- 本用户能写、其他用户/中央秘密拒绝、链接逃逸拒绝、网络边界明确、Job 回收通过，才算基础隔离证据。
- 带补丁 App Server 完成 initialize/Thread/Turn，并与模型代理、目标 Local Agent 完成任务，是另一层运行证据。

**模型传输是独立设计缺口。** 现有 Worker 使用 `http://127.0.0.1:<port>/v1`；AppContainer 默认网络限制可能同时阻断模型代理。不能用全局 loopback exemption 或开放全部本机网络来掩盖问题。

建议优先验证 Windows 专用、按 Worker 授权的命名管道或继承通信句柄，再由中央可信代理访问上游；需要给固定版本模型 HTTP 客户端增加相应适配。正式选定前须证明通道归属、并发流式响应、取消、用户撤销与句柄继承边界。此方案尚未实现，也不是已获验收的 Windows launcher。

另一候选是经严格验证的受限令牌加精确网络策略。若原型证明必须增加管理员安装步骤或系统组件，应先提供实测影响再确认，不能在安装器中静默加权限。

### 推荐的最小验证路径

```text
无网络 capability 的 AppContainer Worker
  ReqwestTransport → reqwest windows_named_pipe
       ↓ HTTP/1.1 + SSE，按 Worker 实例授权的本地管道
  中央可信原生管道端点
       ↓ 仅转交固定 ModelCredentialBroker，不允许选择目标
  现有模型代理的请求限制、用户绑定、SafeSse、撤销与上游 TLS
```

首选复用 HTTP/SSE 而不新增模型消息协议。Rust 在模型专用路径构造 `windows_named_pipe` 客户端，关闭代理发现、重定向和请求正文日志；沿用 `ReqwestTransport::new` 或 `from_http_client`。管道不存在或拒绝访问时明确失败，不能退回 TCP。只允许受管 Worker 模式与原生提供的管道标识进入此分支；不能把任意用户 provider URL 自动转换成管道连接。

中央端优先用原生层创建和管理管道的 ACL、身份及实例，再接入现有 `model-credential-broker.ts` 的固定处理链。P0 可由可信桥接层转交给现有代理的固定 loopback 地址，但 Worker 本身始终不获 loopback 权限；桥接不是任意 TCP 代理，不接受 CONNECT、任意 URL 或管理路由。正式实现可将代理业务处理从监听方式中抽取。单纯把 Node `server.listen` 改成管道路径，只能证明 [Node 支持 IPC](https://nodejs.org/api/net.html#ipc-support)，不能证明按 AppContainer 的授权已完成。

保留每 Worker 的短期模型 lease；管道实例必须绑定同一 lease/用户/Worker 启动身份，不能把来自任意管道的有效 token 当成任意用户访问权。中央上游登录仍只在模型代理内使用。现有只允许 `POST /v1/responses` 或 `/responses`、限制正文/并发、过滤上游返回、禁跨会话引用的规则继续生效。压缩保持关闭，与代理拒绝 `content-encoding` 的现状一致；compact、models、Realtime/WebSocket 等未支持路径明确拒绝，不顺带扩权。

### 进入真实模型前必须实测的门槛

1. **命名空间与身份。** 使用本项目真正的 `CreateAppContainerProfile` 启动方式，验证完整可信进程到无网络 AppContainer 的管道打开；记录名称、登录会话和 SID。不能用两个普通 Win32 进程相通代替。Microsoft 对打包应用的 `LOCAL` 和跨包限制有单独说明，应作为排查依据，不能直接假定等同于本项目未打包 Worker：[IPC 边界](https://learn.microsoft.com/en-us/windows/apps/develop/communication/interprocess-communication)。
2. **端点防冒充。** 原生创建受限 DACL、必要低完整性标签、拒绝远程客户端，并在 Worker 启动前独占创建实例。A Worker 只能接 A 端点；B、未授权本机会话、网络客户端、已退出的旧 Worker 均拒绝。验证管道名预占、额外服务器实例、重启换实例和端点身份检查。
3. **不能忽略 GENERIC_WRITE。** 本版 Tokio 1.52.3 `named_pipe.rs:2540` 默认请求 `GENERIC_READ | GENERIC_WRITE`；[Microsoft](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights) 明确指出管道泛写权限包含创建实例权限。不能仅授予泛写后宣称 Worker 无法冒充服务端。可先验证预建且始终持有的固定实例池和身份绑定；若仍有竞态，需补精确 access 的打开适配或更严格端点认证，保留为阻塞项。
4. **流式与背压。** 真实 reqwest 经管道发送 HTTP POST，验证分片头部、跨片 SSE、UTF-8、慢读、多个并发 Turn、32 MiB 结果边界、上游异常及断管。不得将 SSE 全部缓存至完成；代理原有过滤和并发计数仍有效。管道忙时有界失败，不自动重放已发送请求。
5. **中断必须覆盖静默流。** `codex-api/src/sse/responses.rs:577` 当前等待 `timeout(idle_timeout, stream.next())`，`:662` 发送事件失败才退出；接收方已关闭但上游不再发事件时，连接可能持续到 idle timeout。候选补丁是在读取时同时等待接收方关闭并丢弃底层流。实测 Turn 中断、Worker 退出、用户停用和 lease 撤销后，管道/桥接/代理 AbortController/上游请求均在期限内结束，计数归零。现有代理在 `model-credential-broker.ts:212`、`:242`、`:273` 已有撤销和连接关闭到上游 abort 的基础，但新增中间层必须保持这一传播。
6. **不扩大网络及秘密边界。** 成功使用模型管道期间，Worker 直连 loopback、LAN、外网仍被拒绝；不能获得中央上游密钥、其他 Worker 的 lease、通用继承句柄或管理接口。保留无 capability、Job 回收和客户端执行架构。

若命名空间或防冒充验证失败，第二候选是原生预连接并仅继承/复制明确列出的管道句柄。Tokio `NamedPipeClient::from_raw_handle` 可接管这类句柄，但 reqwest 当前公开选项接收的是管道路径，不接收现成句柄；此方案需要新增 `HttpTransport` 实现或局部 connector 补丁，并处理多请求复用、取消与句柄所有权，改动明显更大。受继承 socket 同样没有现成的 reqwest 接入点，且还需验证其网络权限语义，因此不作为第一候选。以上任一路径均不得用全局 loopback 豁免、放开全部本机网络或向 Worker 下发上游秘密代替。
