## 客户端构建与发布

以下命令在 `spikes/local-dev/` 的目标原生系统执行，先确认无占用同一 Cargo target 的进程。

```powershell
npm run package:desktop
# 生成 Windows updater 包时使用既有签名配置：
npm run package:desktop -- --updater
# 隔离 RC 只读计划，不构建、不安装：
node scripts/package-desktop.mjs --rc --plan
```

默认产物在 `target/desktop-package/<target>/release/bundle/`，`--debug` 对应 debug。脚本先构建并暂存匹配架构的 Agent，再用 `externalBin` 打包；不要绕开脚本漏掉 sidecar。Windows GUI 子系统与运行库依赖都会校验。macOS 按原生架构生成 `.app`/DMG；Intel Mac 尚无本批制品。

Windows 签名器读取 `TAURI_SIGNING_PRIVATE_KEY` 或忽略目录 `secrets/updater.key`。私钥只留受控签名机并独立备份，不提交 Git、不上传中央或写日志。Mac 原生构建 `.app`/DMG，将 `.app` 压成 `.app.tar.gz` 后按既有签名流程处理；DMG 用于首次安装，签名 tar 包用于更新。

`publish-client-release.mjs` 校验平台包旁的 `.sig`，生成不可变版本文件、SHA-256 和 `latest.json`，不会自行上传或切换正式服务：

```text
node scripts/publish-client-release.mjs --version <新版本> --notes-file <说明文件> --windows <安装器.exe> --macos-arm64 <client.app.tar.gz> --out <新的暂存目录>
```

版本参数不能代替源码版本和说明的准备。中央受管服务默认读取 `<dataDirectory>/client-releases`，独立网关用 `PLATFORM_CLIENT_RELEASE_DIR`。先放完整版本文件，最后原子替换 `latest.json`。如需更新网关功能，重新构建并核验完整运行包，不能直接改已安装包内固定哈希资源。

## 应用内更新与恢复

0.2.0 起有更新入口，更早版本须先手工安装支持更新的版本。客户端配置读取后自动检查一次，也可在“设置→版本更新”手动检查。只对更高版本提示更新。

原生层使用已配对 CA 和设备凭据，只接受同一中央 HTTPS 源及 `/client-updates/files/`，禁止代理/重定向。下载上限 512 MiB、十分钟超时，minisign 校验通过后才允许安装。页面不接触凭据、下载 URL 或安装器路径。

安装前检查本机与中央活动任务、文件操作和未发送草稿。`/client-updates/prepare` 对该设备建立六十秒维护租约；其他设备不受影响。桌面等待自己的 Agent 停止后交给系统安装器。`release` 需匹配租约 UUID，重启 `resume` 需匹配预期版本，异常退出由租约超时恢复。恢复文件 `client-update-attempt-v1.json` 不保存 bearer 或租约。

安装器接管前可恢复旧 Agent；接管后失败可能需重开旧客户端或完整安装包修复，不保证自动回滚。发布清单和下载已验收，真实完整“低版本→高版本”应用内安装、配对保留和重连仍需专用设备验收。

## 中央构建和切换

Windows QA 构建入口：`node scripts/package-central-qa.mjs --version 0.1.1`；只读安装核验：`node scripts/verify-central-qa-installed.mjs --build <成功构建目录绝对路径>`。脚本不自动安装或启动。QA 标识、程序名和安装目录独立；安装/卸载保留 AppData 与中央数据，不能替代设备撤销或凭据清理。

Mac 构建入口为 `scripts/package-central-macos.mjs`。运行包清单在 `harness/central-service-catalog.json`。先签内嵌 Mach-O 再生成资源哈希，最终验证 App 和 DMG。需要时仅对构建 shell 设置 `DEVELOPER_DIR=/Library/Developer/CommandLineTools`，不改全局 Xcode 选择。

切换必须确认无活动任务，正常停止并确认全部受管进程退出，备份旧 App、配置和完整中央资料；核验新包后通过原生修订号接口切换，保留用户、配对、证书和历史。原生整包预检曾耗时约三十四秒，运维超时应覆盖真实校验时间，不能跳过完整性检查。
