# 远舟开发入口

这里是工作客户端、中央管理 App、中央网关和 Local Agent 的现有主工程。维护基线为 2026-09-21；功能、部署状态和操作说明见[文档导航](README.md)。

本机项目功能已随客户端 0.2.3 发布，中央网关已部署；使用方式见[客户端项目说明](客户端维护手册.md)，协议与目录快照见 [AgentRPC](../AGENTRPC.md)。项目回归入口为 `node tests/smoke/project-gateway-smoke.mjs`，可选 `--ui` / `--native-ui` 的环境要求及验收边界见[验证手册](验证与已知限制.md)。

## 架构

```text
工作客户端 UI ── WSS /ws ── 中央网关 ── stdio ── 按用户 Codex App Server
                               │ 工具请求编排
客户端 Local Agent ── 出站 WSS /ws/agent
       └─ 本机文件、Git、PowerShell、命令
中央管理 App ── 原生层 ── 本机中央配置、模型认证与受管服务
```

中央系统操作只用于中央自身管理。模型任务所需的客户端文件与命令必须经目标 Agent 执行；客户端不依赖本地 Codex，SSH 不进入产品链路。

## 环境与运行

- Node.js 24.x、npm 11.x（以仓库根目录 package.json 为准）。
- Rust 工具链按 rust-toolchain.toml；固定上游编译信息另见 harness/upstream.json。
- Windows：MSVC C++ Build Tools、Windows SDK、WebView2；macOS：可用的 Apple Command Line Tools。
- macOS 可在构建 shell 设置 `DEVELOPER_DIR=/Library/Developer/CommandLineTools`，不修改全局工具链。

以下命令在仓库根目录运行：

```powershell
npm ci
# 工作客户端，自动构建/启动 Local Agent：
npm run dev:desktop
# 中央管理 App（按任务择一启动）：
npm run dev:central-app
# 仅中央页面预览：
npm run dev:central-ui
```

中央原生与浏览器入口共用 1422，不要同时占用。只预览工作客户端可运行 `npm run web:dev --workspace @central-codex-spike/desktop`，浏览器不具备原生配对和 Agent 生命周期，不能当作完整桌面验收。

当前中央 `wss://192.0.2.10:4510/ws` 使用一体配对码。具体配置、默认输出目录和开发覆盖见[客户端手册](客户端维护手册.md)。首次配置就绪前不启动正常业务连接。中央开发需要受信完整运行包、TLS 和专用数据目录，见[中央管理手册](中央管理维护手册.md)。

### 开发版更新按钮预览

在本机 `apps/desktop/.env.development.local` 设置 `VITE_PREVIEW_UPDATE_BUTTON=1`，可在没有可用更新时显示设置行右侧按钮，核对图标、颜色及悬停展开；提示标记为「更新（开发预览）」。此文件由 Git 忽略，设为 `0` 或移除此项即可关闭；Vite 会重载环境配置，未自动生效时重启前端开发服务。

预览仅控制侧栏入口显隐，点击仍进入真实版本更新页，不改变更新检查结果、下载或安装状态；有真实更新时优先显示真实版本信息。入口同时受 `import.meta.env.DEV` 限制，正式构建不会启用。

## 检查

图片生成专项（2026-10-09）：先构建共享类型与网关，再运行 `node tests/smoke/image-generation-smoke.mjs`。Mac 上新编译的固定 Harness 运行 `node harness/image-generation-smoke.mjs <codex-app-server绝对路径>`；它已加入原生运行包构建门禁。UI 检查为 `node tests/smoke/image-generation-ui-smoke.mjs`，设置 `IMAGE_NATIVE_EXE` 可使用已有隔离 Windows Tauri（开发地址 1423，CDP 9231），不要指向安装版。

真实生图探针 `tests/smoke/image-generation-live-smoke.mjs` 需要隔离认证 WSS 网关和原生测试客户端/Agent；设置 `HARNESS_GATEWAY_URL`、`QA_CA_FILE`、`QA_HANDOFF_FILE`（临时测试账号文件），禁止连接正式 4510。会发送一次真实模型生图请求、保存并校验文件、恢复历史，结束撤销本次测试设备。报告写入忽略的 `target/image-generation-live-*`；账号文件不提交、不输出。它不属于日常无模型测试。

计划/目标改动先构建中央，再运行 `node tests/smoke/task-control-smoke.mjs` 与 `node tests/smoke/task-control-gateway-smoke.mjs`；UI 运行 `node tests/smoke/task-control-ui-smoke.mjs`。原生中央固定二进制运行 `node harness/plan-goal-smoke.mjs <codex-app-server绝对路径>`（确定性模型服务，无正式账号）。真实链路脚本 `tests/smoke/task-control-live-smoke.mjs` 需要独立测试网关 `HARNESS_GATEWAY_URL`、公共 CA `QA_CA_FILE`、一次性测试账号文件 `QA_HANDOFF_FILE` 和现有 `target/debug/examples/central-live-client.exe` / `target/debug/local-agent.exe`；禁止指向正式 4510。仅在测试网关 idle 为 1 秒时使用 `QA_IDLE_RECOVERY=1`，验证 Worker 回收恢复。账号文件及产物只放忽略目录，勿输出或提交。

语言切换回归：`node tests/smoke/language-ui-smoke.mjs`（真实 App 与隔离网关夹具、双语/双主题/窄窗口）。Rust 偏好验证：`cargo test -p desktop-spike language::tests --locked`。Windows 原生验收使用独立应用标识和端口，先设置 `TAURI_CONFIG={"identifier":"com.centralcodex.harnessqa.language","build":{"devUrl":"http://127.0.0.1:1423"}}`，以 `cargo rustc -p desktop-spike --bin desktop-spike -- -o <仓库绝对路径>/target/language-qa.exe` 构建隔离开发二进制，再设置 `LANGUAGE_NATIVE_EXE` 为它的绝对路径，运行 `node tests/smoke/language-native-smoke.mjs`。测试占用 1423/9226、使用独立数据位置，关闭测试进程；不可指向正式安装版。构建 override 仅用于该次命令，不要保留到正常开发/发布环境。证据在忽略的 `target/language-*`；验收限制见验证手册。

Markdown 展示专项回归：`node tests/smoke/markdown-ui-smoke.mjs`，使用真实组件、浏览器及独立 Local Agent IPC 测试图片身份/版本。Windows 原生模式先以 `TAURI_CONFIG={"identifier":"com.centralcodex.harnessqa.markdown"}` 构建开发客户端，再设置 `MARKDOWN_NATIVE_EXE` 为该开发二进制绝对路径，执行同一脚本并加 `--native`。脚本占用本机 1420/9224、使用独立测试页面并退出测试进程，不发送模型任务。不得指向正式安装客户端；需允许隔离 WebView2 配置/缓存目录写入。测试结果位于忽略的 `target/markdown-ui-*`。原生组件检查不等同于真实中央模型整链路验收。

```powershell
npm run check --workspace @central-codex-spike/desktop
npm run build --workspace @central-codex-spike/desktop
npm run check --workspace @central-codex-spike/central
```

## 协议探针与旧开发入口

`npm run smoke`、`npm run protocol:test` 使用 Fake Central/协议夹具，只作开发回归。先按脚本要求构建 Agent 和类型包；协议成功不能代替真实模型或原生 UI。

`dev` / `dev:desktop` 为正常工作客户端入口，`dev:central-app` 为中央管理 App，`dev:gateway` 为真实中央网关。`dev:central-browser` 在运行该命令的机器启动中央网关和浏览器，仅用于指定的中央开发环境。

早期探针统一使用 `probe:` 前缀：`probe:app-server-desktop` / `probe:app-server-browser`、`probe:app-proxy`、`probe:fake-desktop` / `probe:fake-browser`、`probe:fake-central` 和 `probe:agent`。代理与 Fake Central 源码位于 `tests/support/`，不属于产品运行链路。

`legacy:setup-env` / `legacy:db-init` 仅初始化 `legacy/database/` 中的早期 SQLite PoC，不是受管中央启动、正式数据库升级或历史导入步骤。旧明文模式、Day5 和 mTLS 探针按各自夹具使用，不能替代当前 WSS + device-token-v1 链路。

## 2026-09-21 目录迁移

原 `spikes/local-dev/` 主工程整体提升到仓库根目录，`services/test-gateway/` 更名为 `services/central-gateway/`，对应 npm 包更名为 `@central-codex-spike/central-gateway`。其他包名、应用标识、配置和数据目录、网关环境变量与协议标识保持兼容。开发说明移至本文，设备协议仍在根目录 `AGENTRPC.md`。

迁移后在根目录执行 `npm ci` 重新建立 workspace 链接。Rust/Tauri 构建缓存包含绝对路径；其他机器建议使用新的 `CARGO_TARGET_DIR` 重新构建，不直接复用搬迁前的缓存。脚本从根目录运行：构建资源位于 `scripts/build/`，打包发布位于 `scripts/release/`，运维位于 `scripts/maintenance/`，回归位于 `tests/smoke/`。打包仅在用户当次明确要求时执行。

历史验收报告、固定上游清单和运行包目录中的原始路径仍按生成时的布局解释。本机旧目录可能保留未提交的历史产物、缓存、运行数据与 `.env`；没有递归清理，也不再作为开发入口。中央机当前部署和其他机器的旧检出目录未迁移，不能把新的源码路径当作已部署路径。

真实中央验收脚本默认仍从旧中央检出调用配对管理工具；只有中央源码目录也已迁移后，才设置 `CENTRAL_REMOTE_SOURCE_LAYOUT=root`。`npm run layout:check` 可检查工作区链接、锁文件、命令入口、Cargo 成员以及固定运行包许可来源。
