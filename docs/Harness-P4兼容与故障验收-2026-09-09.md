# Harness P4 兼容、故障与运行恢复验收

本轮由用户确认推进：旧会话兼容、真实故障回归、认证刷新与中央重启恢复。
范围保持在原 worktree 的 `spikes/local-dev/` 和中央独立 4529 QA。
正式 4510、安装版配置、原项目未提交改动与 stash 不在本轮修改范围。

本轮实现与有界验收已完成；所有 QA 进程已停止，尚未发布到正式环境。

## 实现变更

- 网关状态文件改为同目录临时文件写完、fsync、rename，中央 macOS 同步目录；
  损坏 JSON、错误版本、重复归属或不可读文件明确拒绝启动，先校验再启动推理进程。
  保存失败停止运行时并报告 `GATEWAY_STATE_UNAVAILABLE`，不继续假报持久化成功。
  旧 v1 根/entry/summary 的未知扩展字段保留，Thread 绑定仅增加字段。
- 修正旧 `device_exec` 描述中的绝对 cwd 许可；实际强制绑定一直只允许工作区相对 cwd。
  恢复旧工具表时注入明确规则：args 必须是数组，cwd 省略或使用 `.`。
  原生图片生成不可用与旧输出仍可读取的说明保持一致。
- Windows Agent 在创建命令前加入不可脱离的 Job，唯一不可继承句柄持续到进程退出。
  `KILL_ON_JOB_CLOSE` 不依赖 Rust 析构，Agent 被 `TerminateProcess` 时后代也退出。
  Job 安装失败明确报错，不降级为可能遗留进程的模式；Unix 行为未改。
- 共享只读认证在启动器中强制禁止刷新/撤销网络请求；正式登录更新仍由凭据所有者管理。
  网关把该模式的过期错误译为 `CENTRAL_SHARED_AUTH_EXPIRED` 及明确操作说明。

旧会话 fixture 入口只有在两个显式 QA 开关、非 4510、`harness-` 用户/设备下才可用，
工具表固定为旧三工具，不接受工作目录、工具或权限覆盖。默认产品路径禁用该入口。

## 旧会话、附件与输出

使用真实中央 Rust App Server 创建旧三工具表、旧 v1 元数据形态的隔离迁移样本，
经过真实模型回合形成 native rollout，再恢复、续聊、归档与恢复。
这是旧格式兼容样本，不宣称读取了全部正式历史或已迁移生产数据。

已验证的联合场景包括：

- 旧 `device_exec` 保留程序 `codexia.workspace` / `codexia.files` 路由到真实 Windows Agent。
- 客户端规则、搜索、读取、补丁一次审批、真实文件输出和计数器单次执行。
- 丢弃提交响应后先查询提交状态；同 clientMessageId 返回原 Turn，文件不被再次修改。
- 归档前后附件与输出的真实路径、版本、大小和 SHA-256 一致。
- UI 历史转换后附件/输出各一张卡；保存副本、幂等保存、过期版本拒绝均有真实文件证据。

详细证据见 [历史兼容](harness-history-live-validation.md) 与
[附件和输出](harness-artifact-history-validation.md)。

## 故障与恢复矩阵

`scripts/harness-fault-live-smoke.mjs` 连接真实中央 4529 和真实 Windows Agent。
Windows loopback 中继只转发真实文本帧并按场景丢弃特定响应/连接，不生成模型或设备结果。

| 场景 | 状态 |
| --- | --- |
| 操作前 Agent 离线 | 通过，明确拒绝 |
| 命令超时 | 通过，进程退出，没有完成标记 |
| 执行中 Agent 网络断线 | 通过，结果未知且不自动重试，进程取消，Agent 可重新连接 |
| 写入完成但响应丢失 | 通过，重新读取实际文件后确认一次写入，没有重放 |
| Agent 进程被强制结束 | 旧版本复现孤儿；新 Job 版本通过，后代退出 |
| 原生窗口执行中关闭 | 通过，desktop→Agent→Node→子→孙全部退出，32 秒后无完成标记 |
| 模型补丁审批拒绝/冲突/停止/客户端断线 | 通过；拒绝/停止/断线不写入，冲突保留外部改动，过期批准无效 |
| 模型补丁已写入但回包丢失 | 通过；实际文件已修改，工具状态未知，仅派发一次，不重放 |
| 原生 Turn 停止 | 通过；真实客户端进程退出，工具终态 cancelled |
| 中央 runtime 崩溃后恢复 | 通过；客户端命令取消，工具结果未知，新提交拒绝，无本地推理回退 |
| 执行中网关重启 | 通过；绑定/历史/提交记录保留，同 clientMessageId 返回原 Turn，命令仅派发一次 |

强制结束缺陷在旧 Agent 上实际复现：Agent 已离线，命令 PID 在 10 秒期限后仍存活；
测试只清理了其自己创建并记录的 PID。修复后同脚本全通过，Windows Job 不需要中央执行。
原生验证的 desktop/Agent/父子孙 PID 为 19500/15876/18532/21148/20876，全部退出。

两次重启恢复读回的原生 Turn 状态均为 `interrupted`，未留下假运行状态。
`conversation.message.status=sent` 表示原提交已接收，不表示执行成功；重复提交仅返回原 Turn。
最终真实模型故障、runtime 崩溃和直接网关重启的结构化证据见
[p4-acceptance.json](../spikes/local-dev/harness/verification/p4-acceptance.json)。

## 认证与状态持久化

只读 auth 符号链接原来不能阻止共享 token 被旋转：上游先请求刷新，再持久化文件。
真实 Rust + 独立假凭据/loopback 端点已复现此顺序，并验证新的保护：

1. 无保护的假共享链接：刷新请求发生，随后 OS 拒绝写入；复现风险。
2. 独立可写假凭据：刷新一次、持久化成功，重启读取更新值，不重复刷新。
3. 受保护假共享凭据：刷新网络请求为零，原文件不变，过期请求在 119 ms 内失败终结。

正式共享凭据没有触发刷新、撤销、复制或输出内容。实际已有 access token 的中央模型调用
继续通过。正式长期凭据策略仍需独立授权登录或凭据服务，不能把本轮共享只读 QA 当作 P5。
详见 [认证生命周期](../spikes/local-dev/harness/auth-lifecycle.md) 和
[长期运行证据](../spikes/local-dev/harness/verification/long-running-qa.json)。

状态文件 15 项真实文件测试通过，包括旧字段保留、坏数据拒绝、失败保护、临时文件清理和
并发读取不出现部分 JSON。Windows 并发共享锁造成的 rename `EPERM` 如实计为拒绝提交，
不宣称所有尝试成功，不改变中央 macOS 的运行架构。实际中央 macOS 15 项全部通过：
11,368 次并发读取，80 次提交全部成功，覆盖真实 fsync、原子替换和目录同步分支。

## 验收边界

- 本轮是有界故障/恢复测试，不是连续多日运行或负载容量承诺。
- 旧原生生成图片能力仍禁用；历史已保存输出继续可读，不重建官方桌面功能。
- 旧图片附件只有 deviceId 的历史结构，不宣称具备重装后设备密钥的强身份保证。
- 正式旧数据全量迁移、独立 macOS 客户端、安装升级与 P5 认证/租户隔离仍独立验收。
