# Worker 权限与模型凭据隔离：P5 第三批

用户确认范围：中央 Worker 文件与进程访问限制、模型凭据隔离、新用户配置与失效恢复，以及独立 4529 验收。本批实现与下述验收已完成，隔离服务已停止，未发布，正式 4510 未更新。

## 运行方式

认证网关启动时要求 `PLATFORM_MODEL_BINDINGS`、`PLATFORM_WORKER_BINARY` 和 `PLATFORM_WORKER_BINARY_SHA256`；`PLATFORM_WORKER_MODEL` 可指定默认模型，本轮采用已在中央验证的 `gpt-6-astra`。缺少配置、二进制哈希不符、平台不支持时拒绝启动；不回退到无沙箱 Worker。`CODEX_BIN` 仅保留给旧非认证链路及明确标注的本地协议夹具。

中央网关内的模型凭据代理只监听随机回环端口。Worker 获取独立随机访问令牌，只有该用户的授权有效时才能调用模型。代理原地读取中央凭据文件，注入上游认证；Worker 的环境和目录不包含真实模型凭据，平台令牌、SSH agent、动态加载和代理环境变量也不继承。

每个 Worker 使用固定哈希的 Rust App Server 和 `harness/worker-isolated.sb`。允许自己的 home/runtime 读写，以及指定模型代理端口；拒绝其他用户文件正文与写入、任意程序启动、钥匙串 Mach 服务和额外出站连接。文件 metadata/existence 与系统只读运行库仍有必要许可；不承诺隐藏其他路径的存在性。同 UID 的非沙箱运维进程、网关进程与操作系统仍是信任边界，不能把本方案称为独立 OS 登录账号或虚拟机隔离。

旧 home 中的 `auth.json` 或非本服务管理的 `config.toml` 不会被覆盖迁移，启动明确拒绝。正式共享历史迁移需另外设计可恢复步骤。受信二进制与沙箱配置不得位于 Worker 目录内；代理配置及任何 provider 凭据也必须位于全部 Worker 可写根目录之外。

## 模型访问配置

在中央机独立、当前运维账号所有且权限 0700 的配置目录保存 JSON，文件权限 0600，禁止软/硬链接。格式如下（使用真实平台用户 ID 和中央凭据路径替换示例值）：

```json
{
  "version": 1,
  "users": {"platform-user-id": {"providerId": "central-account", "enabled": true}},
  "providers": {
    "central-account": {
      "id": "central-account",
      "kind": "chatgpt",
      "credentialFile": "/absolute/operator-owned/auth.json",
      "baseUrl": "https://chatgpt.com/backend-api/codex"
    }
  }
}
```

`chatgpt` 使用中央既有登录文件中的 access token/account ID；代理不刷新、撤销或复制登录，过期由凭据所有者在原登录流程更新。`api-key` 使用仅中央保存的 `{"apiKey":"…"}` 文件与 `https://api.openai.com/v1`。多个用户可以明确绑定同一中央模型账号，其计费和上游配额共享；Worker 访问令牌、文件和会话仍按平台用户隔离。独立上游计费需要独立 provider 凭据。

运维入口为 `scripts/model-access-configure.mjs`，仅在中央 Mac 运行。设置 `PLATFORM_AUTH_FILE`、`PLATFORM_MODEL_BINDINGS`、`PLATFORM_WORKER_ROOT` 后，通过 stdin 提交 `{userId,enabled,provider}`；既有绑定停用/恢复可只提交 `{userId,enabled}`。配置由单一运维进程串行更新；工具核验平台用户和私有文件权限、原子保存并 fsync，不接受模型 key/token 正文，也不把秘密放进命令参数。既有 provider 定义不同会拒绝，防止隐式影响其他用户。

凭据代理每次请求读取当前配置和凭据，并周期性核对存量授权。停用或改绑会撤销该用户令牌、中断其上游流并停止所属 Worker；其他用户继续运行。恢复授权后重新连接创建新 Worker/令牌，再恢复原历史；旧 Turn 与设备命令不自动重放。凭据缺失、停用、过期及上游拒绝显示稳定错误码与恢复建议。认证用户 GET `/model-access` 只能查看自己的安全状态，传入其他 userId 不改变查询归属。

代理只提供 Responses POST；禁止登录/刷新/删除/任意 URL/重定向，强制 `store:false`。拒绝上游历史、会话、文件和模板引用；会话与缓存标识在代理按用户重新生成。非成功响应正文及 SSE 错误诊断不会直接回传，审计只记录用户、动作和稳定错误码。
