## 构建与运行方式

在 `spikes/local-dev/` 使用 `npm run package:desktop`。脚本按 `rustc --print host-tuple`
选择目标，显式将同一 target 传给 Agent 与桌面 Cargo 构建，使用锁定依赖；通过 Tauri
`externalBin` 封装 Agent。`--debug` 可用于调试包，默认是 release。

默认构建缓存 `target/desktop-package/` 与正在运行的开发版本隔离。暂存
`src-tauri/binaries/` 被忽略，不提交二进制。普通 `cargo check/test`、`dev:desktop` 和
原 `tauri:build --no-bundle` 入口不要求提前准备打包 sidecar。源码中的 fixtures 不进入安装包。

- Windows：NSIS `currentUser`，不把 Agent 注册为系统服务；桌面 release 使用 Windows GUI
  子系统，PE Subsystem 实测为 2，不打开额外控制台。
- Mac：包内 `Contents/MacOS/desktop-spike` 与 `local-agent` 相邻；读取包内 Agent 的绝对路径，
  与原 Rust 管道及退出清理方式一致。未新增 JS 执行命令权限。
- DMG 第一次因远程 Finder 排版 AppleScript 等待失败，已采用官方支持的 CI 路径省略该美化步骤。
  不修改录屏/辅助功能权限；包内应用及 Applications 拖入链接仍可用于安装。
- Windows 第一次解压 NSIS 缓存被沙箱拒绝，按权限流程重试后成功。NSIS 及辅助 DLL 由 Tauri
  下载并校验哈希，未改变客户端运行依赖。

实现依据：[Tauri sidecar](https://v2.tauri.app/develop/sidecar/)、
[Windows installer](https://v2.tauri.app/distribute/windows-installer/)、
[DMG CI 支持](https://tauri.app/release/tauri-bundler/v2.2.0/)。

## 首次配置与升级

没有已保存配置且没有开发 fixtures 时，Rust 返回 `needsSetup=true`，不启动 Agent。
内嵌 UI 自动进入原设置页，自动预填系统账号名作为用户 ID、电脑名加安装 UUID 短段作为设备 ID，
并预填“文档/Codexia Workspace”。完成“保存并应用”后才创建默认目录、启动 Agent 并连接中央。
所有字段都可编辑；预填未确认不是错误或无限 loading。

release 不使用相对开发目录；已有配置文件继续沿用，应用 identifier 和设备标识不变。
配置损坏、目录无效、进程启动或保存失败保留明确错误及重试入口。首次保存失败不会声称
“原 Agent 恢复失败”；只有原来存在 Agent 才执行回滚。首次失败也不会误发中央连接。

内嵌前端固定中央网关模式，忽略旧的开发传输模式偏好；Vite 开发服务器仍可使用协议调试模式。
`CODEXIA_*` 开发覆盖仍保留，页面显示来源。未实现新认证、WSS 或自动更新。
