## 最终行为

以下自由路径与默认输出目录规则适用于声明 `client-paths/v1` 的新版 Agent。2026-09-14 后续已恢复此前可用旧客户端的兼容：具有 `remote-workspace/v1` 和现有认证/设备身份能力的旧版继续使用原工作目录、旧输出默认位置及补丁预览协议；不要求升级。缺少既有认证或远程工作区基础能力的更早版本不在本次兼容范围。

- 列目录、读取、搜索、项目规则、补丁、Git、命令 cwd、附件和输出接口统一接受本机绝对路径及相对路径。相对路径以配置目录为起点，允许父目录路径。Windows 盘符绝对路径、UNC 文件路径和显式目录链接可解析；不接受含糊的盘符相对路径、设备命名空间等非普通文件路径。
- 用户指定其他项目时直接使用该目录，无需移动项目或更改输出配置。项目规则按实际目标目录的祖先链读取，Git 支持其他目录及普通 worktree；递归搜索仍有分页/大小/超时上限并跳过链接，避免循环，显式访问链接可用。
- 未指定 path、仅提供 name 的文档、复制输出以及内联图片保存到默认输出目录。显式 path 保留。`file/output_paths.outputDirectory` 是默认保存位置；`workspace` 保留旧字段兼容，`downloads` 仅报告真实下载目录。既有输出文件不迁移。
- 设置显示“默认输出目录”，文件面板接受绝对路径，Windows 盘符根目录和 UNC 共享的返回上级/拼接行为已修正。保留配置字段 `workspaceRoot`、环境变量 `CODEXIA_WORKSPACE_ROOT` 和 IPC 名称，升级无需重填配置。
- 已有 Thread 仍绑定原用户和设备安装身份，修改默认输出目录不再使 Thread 不可恢复。每次实际请求及等待审批期间仍校验当次目录配置，防止相对路径在重配置后落到其他位置。
- 补丁预览返回 `expectedPaths`（规范化的实际目标路径）和 `expectedVersions`；审批及执行携带并校验二者，拒绝预览后被重新指向其他目录的链接。冲突、部分成功、未知结果等原有终态保持不变。
