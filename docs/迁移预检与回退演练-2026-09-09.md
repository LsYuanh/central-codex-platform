## 当前结论

新增 `spikes/local-dev/scripts/migration-preflight.mjs`，读取操作人员明确准备的离线公共清单和历史副本，检查账号映射、设备归属、证书公共元数据、历史文件哈希及待核对提交。它不会修改状态、创建账号、签发证书、启动 Worker 或导入历史。所有结果均为 `readyForCutover: false`、`importImplemented: false`。

新增 `spikes/local-dev/scripts/migration-rehearsal.mjs`，自行生成合成数据，在新的 `target/migration-rehearsal-*` 下执行检查、备份完整性和恢复演练。它不接受真实源目录或恢复目录参数，不连接中央机，不读取正式身份库、模型凭据或客户端凭据库。合成证书清单是元数据占位，不能替代真实 X.509 / mTLS 验收。

正式 4510、安装版客户端、原有账号和历史未由这两个工具读取或更改。

## 为什么不能只改 workerLayout

当前 `gateway-state.ts` 的 v1 状态以 `users[旧 userId]` 保存 Thread ID、摘要、附件提交和输出关联；顶层、条目和摘要的未知扩展字段需要完整保留。Thread 原生内容及 App Server 的索引、数据库另存在中央运行时的 CODEX_HOME。网关摘要不是完整历史备份。

`index.ts` 在已有 Thread 且布局不是 `per-user/v1` 时拒绝认证模式启动，错误为 `WORKER_LAYOUT_MIGRATION_REQUIRED`。`worker-manager.ts` 则按平台用户 ID 的 SHA-256 分配独立 `home`、`runtime`。更改状态标记既不能把共享历史正确拆分，也不能证明新 Worker 可访问原生 Thread，因此本次工具始终保留共享布局阻断。

`platform-auth.ts` 的平台用户 ID 与旧客户端可填写的 userId 不等价。设备配对会生成服务端分配的新设备 ID；客户端重新生成签名密钥和 TLS 私钥后，旧 Thread 的设备 ID / deviceKey / remoteWorkspace 绑定不会自动变化。`remote-workspace.ts` 比较 policy、userId、deviceId、deviceKey、workspaceRoot，任何变化都不能通过填写同名设备或直接编辑清单跳过。

映射表只是管理员待审的迁移意图，不是所有权转移授权，也不是运行时可恢复证明。工具检测到变化时输出 `unavailable-binding-changed`，保留历史字节并提示只能新建对话或由原绑定设备恢复。没有原始绑定的旧 Thread 另标记 `LEGACY_BINDING_NEEDS_ORIGINAL_DEVICE_VERIFICATION`。本次未增加改绑功能或历史只读浏览产品入口；“保留”仅指备份中存在原字节。

## 离线输入与使用

在 `spikes/local-dev` 运行：

```powershell
node scripts/migration-rehearsal.mjs
node scripts/migration-preflight.mjs --bundle "C:\绝对路径\已准备的离线清单目录"
```

第一条命令直接生成合成输入、损坏模拟、备份、全新恢复目录和 `result.json`。演练故意破坏自己的 `synthetic-source`；用于复查预检的是运行结果目录中的 `restored`，其中恢复前后的网关及历史字节完全相同。

第二条只读工具要求目录中包含以下文件，不会自行寻找正式源：

| 文件 | 内容与约束 |
|---|---|
| `gateway.json` | v1 网关状态副本，保留所有用户、Thread、摘要及扩展字段；重复 Thread 所有权或结构损坏直接失败 |
| `target-identities.json` | 公共投影：`version:1`、`users:[{id,disabled}]`、`devices:[{id,userId,deviceKey,workspaceRoot,revoked,certificates:[{fingerprint,expiresAt}]}]`；deviceKey、fingerprint 为小写 SHA-256，expiresAt 为毫秒；拒绝 sessions 等完整身份库字段 |
| `plan.json` | `version:1`、`sourceQuiesced:true`、`accounts:[{sourceUserId,targetUserId}]`、`devices:[{sourceUserId,sourceDeviceId,targetDeviceId}]`、`history:[{threadId,files:[{path,sha256}]}]` |
| `history/*` | 清单列出的原生历史导出或副本；每个文件归属单个 Thread，路径相对目录，逐文件 SHA-256 校验；本次验证使用明确带 synthetic 标识的合成 JSONL |

输入路径不允许穿越、绝对路径、冒号、反斜线、符号链接或多硬链接文件，单个文件上限 64 MiB。历史清单不能用三个元数据文件冒充 Thread 历史。尚不支持将一个共享 SQLite 数据库宣称为多个用户已拆分的历史，真实原生数据库导出/导入、索引重建和一致性校验仍待单独实现。

不要将完整 `auth.json`、会话令牌、私钥或模型登录放进公共身份投影。工具按公共字段白名单拒绝误传完整身份库，但不承担扫描所有历史文本中潜在敏感信息的职责。

退出码：`0` 表示有限离线检查通过，仍需真实运行验收；`2` 表示发现迁移阻断；`1` 表示输入结构、路径或文件不安全/不可读。输出只含状态、错误码、Thread ID 和计数，不回显消息正文、设备私钥或证书内容。

主要拒绝项包括：缺少账号映射、账号被禁用、重复/合并映射、设备未映射或归属他人/吊销、证书缺失或过期、原绑定冲突、历史文件遗漏/哈希不符、未确认停止写入、附件提交处于 preparing/submitting/unknown 或输出仍在 saving。未知操作必须人工核对，工具不会重发。

`sourceQuiesced` 是操作者的声明，离线工具无法验证进程是否真的停止；证书指纹和有效期也是公共记录，不证明 CA 签名可信、客户端持有私钥或凭据库可用。真实验收仍须执行服务端证书校验、平台登录、设备 mTLS 连接和原生客户端生命周期检查。

## 备份与回退演练证明了什么

演练只复制固定四个合成文件，写入独占的新备份目录并生成长度和 SHA-256 清单。恢复前先验证全部备份文件，损坏备份会在创建恢复目录前失败；恢复只允许全新目录，不能覆盖已有目录。模拟源数据损坏后恢复原始字节，验证未知扩展字段、附件关联、输出元数据及历史内容原样保留，再次预检仍返回共享布局迁移阻断。

这证明了本地合成文件的完整性检测和恢复流程；没有证明真实 App Server 数据库事务一致性、断电持久性、全量备份覆盖率、生产 RPO/RTO 或正式回退可执行性。备份清单本身需独立保存可信哈希；本次恢复用运行中保留的清单为校验基准，并在结果记录清单文件哈希。没有把可同时被篡改的清单当作可信签名。

## 正式切换前仍需形成的独立交付

1. 在获准读取正式数据后，核对旧用户、设备与每个 Thread 的归属，由实际负责人确认一对一映射。不能按用户名猜测或隐式合并账号。未确认条目保留为隔离历史，不能开放执行。
2. 明确共享原生历史格式及受支持的导出/导入途径，准备逐用户离线副本，在新的隔离 Worker 中验证 Thread 枚举、读取、附件/输出关联、幂等记录及原设备恢复；明确保留旧绑定但不能恢复的条目。不能直接改 workerLayout 或递归复制包含模型登录的整个共享 CODEX_HOME 到 Worker。
3. 制定停止接单、终止/核对活动任务、停止所有写者及一致快照步骤。完整备份需覆盖网关状态、原生历史数据库及相关日志/索引、平台身份状态、模型绑定配置、审计、设备 CA、服务端 TLS 配置和匹配的服务二进制；私钥与身份库仅在中央受限位置备份，不能进入 Worker 或客户端包。本次没有采集这些正式数据。
4. 在两端候选安装包验证配置保留、凭据库可访问、登录和重配对。旧明文网关配置升级与新认证端点切换属于不同变更，需明确执行顺序和用户提示；安装器成功不代表旧对话可恢复。
5. 制定含数据版本的回退步骤：停止新写者，保存切换后的状态供核对，在全新恢复目录验证备份并启动隔离服务，通过验收后才能决定正式指向。禁止旧、新网关同时写同一套数据；切换后产生的新数据不因回退而默默丢弃。恢复旧身份备份可能恢复已吊销会话/设备，必须另行设计失效处理，不能把回退视作自动安全登录恢复。

本次不提供正式切换、原始状态覆写或真实账号迁移命令，以上阻断不能靠离线检查的成功解除。
