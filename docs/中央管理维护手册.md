## 配置和服务生命周期

首次配置依次设置私有数据目录、监听及客户端可达地址、TLS 证书和受信运行包。配置位于应用数据目录的 `config/central-config.json`；Mac 正式应用资料在 `~/Library/Application Support/com.yuanzhou.central`。配置、数据、只读运行包分离。

监听可用 `0.0.0.0`，客户端地址必须是实际可达的 WSS `/ws` 地址，不能是通配、回环或带身份查询参数的 URL。支持端口 1024–65535；证书链、主机名、用途、有效期和私钥匹配均须验证。原生层检查目录所有者、权限、链接和运行包完整性；界面校验不能代替原生检查。

保存使用 `expectedRevision` 防止旧窗口覆盖新配置，原子写入失败保留原值。服务运行或清理未确认时不能保存冲突配置；先在运行概览停止并确认进程退出，再修改。

首次管理员初始化只用于新的专用数据目录，不覆盖已有用户库。选择有效模型账号启动服务；切换账号需要停止再启动，后续同账号令牌续期可热更新。中央 App 及受管服务须保持运行，Codex 桌面可以关闭。当前没有配置开机自启；关闭 App 会停止其网关和 Worker。

原生层持有运行包句柄和数据目录独占锁，经私有 stdio 向网关传递 TLS、模型和初始化材料。Windows 用 Job 管理进程树，Mac 用守护进程及独立进程组。启动须匹配实例并确认监听，停止须确认整个受管进程树退出。超时结果未知先查询状态，不能按新请求自动重复启动或改配。

## 用户、配对和设备

在“用户与设备”用平台管理员登录，创建无密码的配对专用用户，选择用户后生成一体配对码。管理员会话只留原生内存，绑定当前服务实例；普通设备令牌即使属于管理员账号也不能执行管理操作。

配对码五分钟有效、单次使用；同管理员会话对同用户重发会废止此前未消费的码。发码管理员登出、会话失效、目标用户停用都会使码失效。停用用户或撤销设备会关闭相关连接并取消在途客户端命令，记录仍保留。

管理修改按 `requestId` 幂等，不能跨网关重启承诺幂等。请求超时须刷新列表核对结果；不自动生成新 ID 重发修改。设备在线来自当前已认证 Agent 连接，持久化注册不等于在线。

主要 JSON POST 路由：`/auth/admin/login`、`/auth/admin/users`、`/auth/admin/devices`、`/auth/admin/user/create-pairing`、`/auth/admin/user/disable`、`/auth/admin/pair-code`、`/auth/device/revoke`、`/auth/logout`。原生命令集中在 `apps/central/src-tauri/src/people.rs`，网关权限与字段校验在 `services/central-gateway/src/platform-auth.ts`。

## Worker 与审计

每个已验证用户惰性创建独立中央 App Server，用户 ID 的 SHA-256 对应独立 `home/runtime`。Thread、工具、审批和事件绑定用户与 Worker 实例。单个 Worker 崩溃仅影响所属用户，取消关联设备命令；恢复不重发旧 Turn 或修改。过期审批不能批准新实例操作。

| 独立网关变量 | 默认值 | 作用 |
| --- | --- | --- |
| `PLATFORM_MAX_WORKERS` | 8 | Worker 上限 |
| `PLATFORM_USER_TURNS` | 2 | 每用户活动或未知 Turn 上限 |
| `PLATFORM_TOTAL_TURNS` | 8 | 全局活动或未知 Turn 上限 |
| `PLATFORM_WORKER_REQUESTS` | 32 | 每 Worker 待返回 RPC |
| `PLATFORM_WORKER_IDLE_MS` | 300000 | 空闲回收 |
| `PLATFORM_WORKER_RESTART_MS` | 1000 | 重启最短退避 |
| `PLATFORM_WORKER_ROOT` | 网关状态目录下 `workers` | 用户运行目录 |
| `PLATFORM_AUDIT_DIR` | 网关状态目录下 `audit` | 持久审计 |

受管 App 使用保存的并发配置，不能假定任意 shell 环境会覆盖它。超限明确拒绝，未知结果保守占位，不能直接清空状态伪装任务完成。

Worker 不持有上游登录材料，仅获模型代理的有限访问能力。Mac 使用 Seatbelt；Windows 原生隔离与命名管道详见 [Worker Host](../services/windows-worker-host/README.md) 和 [Harness](../harness/README.md)。Job 本身不等于文件或网络隔离；完整 Windows 网络边界仍有验收缺口。

审计记录操作类型、时间、身份/请求标识和结果码，不保存对话、文件正文或令牌。管理员可读 `/audit` 与 `/workers`；审计/网关状态写入失败停止推理，损坏状态拒绝启动。不能以删状态文件方式绕过；先保留现场、核对备份。旧共享历史触发 `WORKER_LAYOUT_MIGRATION_REQUIRED` 时使用[迁移工具说明](历史迁移工具.md)，不能只改布局标记。

## 运行概览与诊断

概览每两秒读取受管实例指标。在线设备仅计 ready 且连接打开的 Agent；活动任务含等待审批/工具/终态的 Turn；模型进程仅计受管存活 Worker，不扫描全机 Codex。十秒以上旧指标隐藏，错误显示未知；只有停止且清理确认后显示零。

“设置与诊断”显示已保存并发配置、故障及恢复建议，手动采集、预览和导出脱敏 JSON。导出时重新采样，取消不写入，已有文件不覆盖；不含目录、地址、用户设备标识、凭据或完整日志，不自动上传。

正式只读状态检查、备份和回退见[发布手册](发布与回退手册.md)；模型失效见[认证手册](模型认证维护手册.md)。

## 个人技能存储与运行边界（2026-09-21，中央已部署）

网关在状态文件同级维护 `personal-skills.json`，保存用户归属、当前修订、启用/自动匹配状态、完整包和设备草稿登记；使用现有原子写入机制。备份和恢复必须包含该文件，不能只备份 Worker 目录。网关不会为 UI 接受的用户 ID/中央路径建立技能权限，身份始终来自已认证连接。修改操作按用户串行，其他用户不能读取、修改或删除技能。

每个用户的 `runtime/managed-skills/` 是可重建的原生发现投影，只含 `SKILL.md`、自动匹配元数据和当前版本目录清单。完整包不下放到 Worker。移除/停用通过清单立即排除；旧投影和客户端副本暂保留。模型实际使用的资源必须由 `device_skill_load` 经 Agent 写到当前绑定客户端并检查 SHA-256，再通过现有设备工具访问。网关不在中央运行技能脚本。

正式 4510 网关和固定 Harness 已升级，Windows 开发版内置新版 Agent 可调用；客户端 0.2.5 安装包和更新清单未变。缺少任一能力时按明确错误处理，不退回扫描中央个人目录。新建对话以获得新增动态技能工具；旧对话保留既有工具快照。真实模型单客户端链路已通过，多机矩阵、Mac 客户端及新 Windows 中央 Harness 仍待验收，不能沿用旧二进制哈希或旧资格结论。

## 远舟内置技能创建器（2026-09-22，未部署）

`src/builtin-creator.ts` 将唯一技能正文随网关编译，运行时生成完整 `SKILL.md` 包，避免运行包漏复制资源。标识 `yuan-zhou-skill-creator`，展示名「创建技能」，来源 `builtin`；不扫描、调用或替换中央系统 `skill-creator`。正文变更必须递增 `CREATOR_VERSION`；修订号为内容版本 × 1,000,000 + 用户设置修订，保持原生投影不可变。`personal-skills.json` 增加按用户 scope 保存的 `builtinPreferences`，旧文件可直接读取；内置条目不占个人技能 100 个/32 MiB 配额，内容不复制入个人存储。

`device_skill_draft({requestKey, skillId?})` 仅创建登记草稿，经认证用户、Thread 和设备安装身份绑定。相同用户/设备/Thread/requestKey 的重试复用草稿；不同创建任务使用新 requestKey。已保存的新建请求返回 `SKILL_DRAFT_ALREADY_SAVED`，不能借重试覆盖已存技能。修改操作与 UI 共享按用户的互斥、超时、断连、设备切换和取消校验；创建成功广播 `skill/changed`。模型不传 userId、deviceId 或目录。完整包仍通过设备工具在客户端生成，由原预览/保存接口保存。

内置内容不能删除、修改或停用，只允许调整自动匹配。个人技能不能保存为保留名称；历史同名个人技能不删文件，目录中标记名称冲突并排除发现，改名后可恢复。新 Thread 持久化 `skillCreator` 工具能力标记；旧 Thread 不提升工具快照，调用时明确要求新对话。

发布时必须配套新的完整中央运行包：固定上游版本不变，受管发现目录上限从 100 调为 101，以容纳 100 个个人技能和 1 个内置技能；`remote-workspace.patch`、生成模板及摘要同步更新。系统/用户/项目目录扫描仍关闭。不要只替换网关后沿用旧 Harness 来验证满额目录。当前正式部署版本仍为前文 2026-09-21 版本，本次仅源码和本地验证完成，真实模型自动触发及新 Harness 二进制链路待独立 QA。
