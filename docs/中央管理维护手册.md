## 原生图片生成（2026-10-09，开发版未部署）

固定 0.156.1 Harness 在 Mac 远程 Worker、Broker 认证和 `CODEX_REMOTE_IMAGE_GENERATION=1` 同时满足时，只放行 `image_gen.imagegen`。网关仅对 ready 的 ChatGPT 绑定设置此启动标记，并核对初始化 `yuan-zhou-image-generation/1` 后发布 `platformCapabilities.imageGeneration` 与内置技能。Windows 中央、API Key 绑定和旧运行包不宣告支持；不新增 API Key 计费回退。

## 原生计划与目标控制（2026-09-24，中央 0.1.3 已部署）

固定 App Server 0.156.1 的远程 Harness 新增 `yuan-zhou-plan-goal/1` 能力标记。只开放内置 `default/plan` 协作模式、计划/追问 handler、目标 get/create/update 工具和 `thread/goal/get,set,clear` RPC；远程 App Server 分支安装原生 goal extension，自动续跑和预算状态由原生后端处理，不通过定时补发用户消息模拟目标。客户端不能提交自定义 developer instructions 或 `deferGoalContinuation`。

网关 `task-control.ts` 校验参数，`index.ts` 负责用户/设备归属、模式幂等和只读工具防线；`worker-manager.ts` 为 active 目标持续预留 Turn 额度。自动轮次没有预留额度时关闭对应 Worker，暂停/完成/清除则仅在当前轮终止后释放额度。冷恢复先暂停持久化目标、重新获取客户端上下文与技能目录并加载线程，再接受明确激活；异步旧 goal 快照不能抹掉激活预留。

停止、暂停和断线先写原生 paused，再按实际 Turn ID 中断；断线或激活取消后的停止失败时回收对应 Worker，用户操作失败则显示可核对错误。历史恢复不自动激活目标；同用户其他设备只能读状态，不能控制绑定设备的目标。计划模式同时在网关和原生 dispatcher 拦截写入/命令/技能资源投影，客户端系统操作始终由 Local Agent 执行。

开发验证使用独立认证 WSS 网关、独立账号/历史、Seatbelt 隔离 Worker、真实 GPT-6 Sol 和 Windows Agent。随后按用户授权将正式中央升级为 0.1.3 / revision 14，同步网关与 Harness；正式测试账号的 Windows 原生设备已验证计划只读、目标写入回读和原生完成/用量，结束撤销临时设备。开发客户端重连可获得能力，已发布的 0.2.9 工作客户端仍缺少入口，尚未另发安装包。原生计划/目标和认证网关回归再次通过，见 [Harness](../harness/README.md) 和发布手册。

## 2026-09-23 App Server 自动更新与模型目录（中央 0.1.2 已部署）

首期覆盖现有 macOS arm64 中央管理 App。`runtime_updates.rs` 在原生层管理完整运行包，不在客户端安装 Codex，也不直接替换为未经远程执行适配的官方二进制。每天检查官方稳定版及项目签名通道；网络/通道失败每小时重试，界面「设置与诊断 → App Server 更新」可安排检查，正常将在 30 秒内开始。Windows 目前明确显示不支持。原生管理器与网关已部署；独立构建/签名 runner 和签名更新通道尚未配置，后续自动发布仍待接通。

更新包必须通过固定公钥 minisign 验签、版本/序列校验、归档大小/摘要校验和逐文件运行包校验。构建、协议 schema 或边界测试有变化/失败时保留旧版本，显示等待兼容包；不向用户显示未经验证的“已升级”。签名私钥不进入中央机、Worker、源代码或构建任务，只允许独立签名任务使用。

切换通过当前网关私有 stdio `stop/idle` 请求；网关在同一个事件循环中检查运行任务、正在启动/退出的 Worker、RPC 和设备请求，并关闭新请求准入，防止“检查空闲后又接到任务”的竞态。旧运行包没有 `runtimeUpdatesReady` 能力时拒绝自动切换，首次启用须升级完整中央 App/网关。停服并确认进程清理后，保留数据根目录所有权锁，复制历史、技能、用户及设备资料；独占服务锁文件不进快照。

新版以 `updateValidation` 模式启动，暂拒绝外部客户端/设备请求；验证中央账号官方目录、Worker `model/list`、`thread/list` 和已有历史的 `thread/read`，成功保存选择记录后 `update/accept` 开放连接。不发送真实模型推理。接受确认丢失时重试确认，不回退已可能接收新任务的数据。此前任何失败恢复上一版及备份数据；恢复保留根目录/锁 inode，以 pending 日志支持中断重试，数据目录发生变化则拒绝还原。失败尝试的数据在同级 `.runtime-failed-*` 留存用于诊断，需人工确认后清理，不混入恢复后的历史。

`runtime-updates/selection.json` 位于原生应用资料目录，包含签名选择记录、原数据目录身份和备份标识。成功后清理为当前包、上一包及本次所需数据备份；签名失败或校验失败包不启用。已失败的包序列不会反复自动尝试，等待更高序列的修复包。仍沿用原生 Debug QA / 生产资格门禁，不代表取得正式 Release 安全资格。

模型目录入口：`services/central-gateway/src/model-catalog.ts` / `model-credential-broker.ts`，精确开放有租约认证的只读 `/v1/models?client_version=X.Y.Z`。中央附加原登录令牌访问官方目录，限制响应大小/超时，拒绝跳转和上游敏感错误；模型能力、推理强度和速度元数据原样交给 App Server 校验。Mac Worker 通过 `CODEX_REMOTE_MODEL_CATALOG=1` 启用 Harness models-manager 的 broker 目录刷新；缓存沿用上游，正常非远程模式不变，Windows Worker 暂不启用此开关。

## 对话历史只读工具（2026-09-22 实现，2026-09-23 已部署）

## 配置和服务生命周期

首次配置依次设置私有数据目录、监听及客户端可达地址、TLS 证书和受信运行包。配置位于应用数据目录的 `config/central-config.json`；Mac 正式应用资料在 `~/Library/Application Support/com.yuanzhou.central`。配置、数据、只读运行包分离。

监听可用 `0.0.0.0`，客户端地址必须是实际可达的 WSS `/ws` 地址，不能是通配、回环或带身份查询参数的 URL。支持端口 1024–65535；证书链、主机名、用途、有效期和私钥匹配均须验证。原生层检查目录所有者、权限、链接和运行包完整性；界面校验不能代替原生检查。

保存使用 `expectedRevision` 防止旧窗口覆盖新配置，原子写入失败保留原值。服务运行或清理未确认时不能保存冲突配置；先在运行概览停止并确认进程退出，再修改。

首次管理员初始化只用于新的专用数据目录，不覆盖已有用户库。选择有效模型账号启动服务；切换账号需要停止再启动，后续同账号令牌续期可热更新。中央 App 及受管服务须保持运行，Codex 桌面可以关闭。当前没有配置开机自启；关闭 App 会停止其网关和 Worker。

原生层持有运行包句柄和数据目录独占锁，经私有 stdio 向网关传递 TLS、模型和初始化材料。Windows 用 Job 管理进程树，Mac 用守护进程及独立进程组。启动须匹配实例并确认监听，停止须确认整个受管进程树退出。超时结果未知先查询状态，不能按新请求自动重复启动或改配。

## 用户、配对和设备

在“用户与设备”用平台管理员登录，创建无密码的配对专用用户，选择用户后生成一体配对码。管理员会话只留原生内存，绑定当前服务实例；普通设备令牌即使属于管理员账号也不能执行管理操作。

配对码五分钟有效、单次使用；同管理员会话对同用户重发会废止此前未消费的码。发码管理员登出、会话失效、目标用户停用都会使码失效。停用用户或撤销设备会关闭相关连接并取消在途客户端命令，记录仍保留。

管理修改按 `requestId` 幂等，不能跨网关重启承诺幂等。请求超时须刷新列表核对结果；不自动生成新 ID 重发修改。设备在线来自当前已认证 Agent 连接，持久化注册不等于在线。

主要 JSON POST 路由：`/auth/admin/login`、`/auth/admin/users`、`/auth/admin/devices`、`/auth/admin/user/create-pairing`、`/auth/admin/user/disable`、`/auth/admin/pair-code`、`/auth/device/revoke`、`/auth/logout`。原生命令集中在 `apps/central/src-tauri/src/people.rs`，网关权限与字段校验在 `services/central-gateway/src/platform-auth.ts`。

## Worker 与审计

每个已验证用户惰性创建独立中央 App Server，用户 ID 的 SHA-256 对应独立 `home/runtime`。Thread、工具、审批和事件绑定用户与 Worker 实例。单个 Worker 崩溃仅影响所属用户，取消关联设备命令；恢复不重发旧 Turn 或修改。过期审批不能批准新实例操作。

| 独立网关变量 | 默认值 | 作用 |
| --- | --- | --- |
| `PLATFORM_MAX_WORKERS` | 8 | Worker 上限 |
| `PLATFORM_USER_TURNS` | 2 | 每用户活动或未知 Turn 上限 |
| `PLATFORM_TOTAL_TURNS` | 8 | 全局活动或未知 Turn 上限 |
