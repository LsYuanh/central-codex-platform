## 用户流程

在现有连接设置填写管理员提供的 `wss://` 中央地址，输入一次性配对码和本机名称，配对成功后确认本机工作区，再点击“保存并应用”。关联用户和设备由中央确定；客户端不输入平台账号密码，不维护设备证书或续期状态。

设置页显示本机授权、关联用户和本机设备。其他设备由管理员在中央管理，客户端没有其他设备列表或跨设备撤销入口。取消本机配对会停止本机连接并尝试中央撤销；若中央未确认，明确提示管理员继续撤销，不能把本机清理描述为中央已经成功撤销。

离线时保留可读的本机配对，但显示“暂时无法确认中央授权”；中央已撤销、授权失效、配对码无效/已使用/过期、本机存储故障分别有明确恢复提示。异步请求带有超时和结果未知状态；旧中央地址的迟到响应不写回新地址。配对、取消配对和 CA 保存期间，与保存工作区配置互斥；运行任务的原有忙碌边界继续生效。

仍严格验证 HTTPS/WSS 服务端证书和主机名。使用系统信任证书时无需额外设置；自建 CA 只配置管理员提供的本机 PEM 公共证书路径。没有关闭 TLS 验证的产品选项。

## 中央 API 和授权范围

认证模式标识为 `device-token-v1`。网关未配置 `PLATFORM_DEVICE_AUTH_MODE` 时使用该默认值；只有显式 `legacy-mtls-v1` 加载设备 CA 并请求客户端证书，无效值启动失败。以下接口已进入网关入口并用于 4529 隔离验收。

| 操作 | POST 接口 | 调用者及输入 |
|---|---|---|
| 管理员登录 | `/auth/login` | 管理员账号密码，获得管理会话；不在客户端配对页使用 |
| 创建/停用用户 | `/auth/admin/user/create`、`/auth/admin/user/disable` | 管理会话；沿用中央用户管理能力 |
| 发放配对码 | `/auth/admin/pair-code` | 管理会话，`{userId}` 指定目标用户 |
| 查看设备 | `/auth/admin/devices` | 管理会话，可按 `{userId}` 过滤；仅返回公开元数据 |
| 管理员撤销设备 | `/auth/device/revoke` | 管理会话，`{deviceId}` |
| 本机兑换配对码 | `/auth/device/pair` | 无 bearer，`{code,name}`；用户身份不能由请求替换 |
| 本机授权状态 | `/auth/device/status` | 本机设备 bearer，空对象；只能查询本设备 |
| 本机取消配对 | `/auth/device/disconnect` | 本机设备 bearer，空对象；撤销本设备 |

配对码有 5 分钟有效期，仅可兑换一次，中央内存只保留其哈希。兑换还核验发码管理员会话和目标用户；网关重启、发码会话失效或目标用户停用后，尚未兑换的码不能继续使用。配对码需要由管理员提供给目标设备使用者，不应进入公开日志、URL 或代码仓库。

设备令牌为 bearer 秘密，只在首次兑换时返回给原生客户端；中央持久状态保留哈希和设备关联。桌面与 Local Agent 使用设备令牌连接各自 WSS 通道，令牌不放入 URL 或 React 状态。通道身份由令牌确定，不能通过 `userId` / `deviceId` 参数冒用其他设备。

**设备令牌没有管理员权限。** 即使目标用户本身是管理员，配出的设备主体仍为普通设备权限，不能发码、创建用户、查看管理设备列表或撤销其他设备；同一账号下的另一台设备也不例外。管理员管理会话与设备连接不能互相代用。

当前设备令牌没有客户端证书续期或刷新令牌流程，持续有效直到撤销或用户停用。中央撤销后，相关既有 UI/Agent 连接失效；撤销、断线期间已发出的工具任务不得自动重放。4529 的 Windows RC4 真实进程取消、UI 停止重连、明确恢复提示及重新配对后的历史边界均已通过。

## 原生存储

原生模块位于 `crates/platform-security/src/device_token.rs`。凭据按应用标识和中央 HTTPS origin 分开保存，路径位于应用数据目录的 `device-auth-v1/<SHA-256>.bin`；令牌通过原生 IPC 内部使用，公开 DTO 仅包含模式、用户、设备和状态信息。

- Windows：当前用户 DPAPI 加密，加上受保护的目录/文件 ACL；检查所有者、ACL、符号链接/reparse 等路径边界。无需 Windows Credential Manager 或交互式 Keychain 授权。
- macOS：当前用户所有的 `0700` 目录与 `0600` 普通单链接文件；拒绝符号链接和不符合权限的路径。**文件内容未加密**，依赖文件权限保护；拥有同一用户权限的进程仍处于信任边界内，不能将其描述为 Keychain、硬件密钥库或加密存储。

配对前检查存储位置，写入采用临时文件和原子替换。存储失败需要保留旧身份并尽力撤销刚兑换的新设备；重新配对成功后尽力撤销旧设备。离线或网络失败时不能保证中央撤销已完成，必须按返回状态显示并由管理员核对。损坏、权限不安全和不可读写的状态要明确失败，不能静默改用宽松文件或其他凭据来源。

Windows DPAPI/ACL 已通过上述本地原生验收；RC3 macOS 实际配对、桌面与 Agent 使用、重启恢复及 `0700`/`0600` 权限已有主任务现场通过结论。本页没有补充独立 macOS 存储专项测试计数，也没有把文件存储描述为加密存储。

## 旧方案、历史与发布边界

旧 `legacy-mtls-v1` 记录保留用于历史追溯；显式兼容模式已通过本地入口及 legacy 专项核验，不能由认证错误触发自动回退。新方案不读取或迁移旧 Keychain/凭据库中的平台登录、签名密钥和客户端 TLS 私钥。

旧设备需要新的配对码重新配对。新设备 ID / deviceKey 不代表拥有旧 Thread 的执行绑定；`userId`、设备和工作区边界继续生效。旧对话被拒绝时保留连接与清晰提示，不能通过改名、同名设备、编辑布局标志或跳过绑定检查恢复执行。共享历史拆分及所有权迁移仍未实现，离线清单和合成备份演练不是生产历史迁移授权。

旧第五批 Windows mTLS 安装/升级/回退成功仍是那个候选包的历史证据；旧 Mac Keychain 验收未完成，但已由用户选择的新方向取代。旧 4529 进程、临时 bootstrap 和 QA 目录应在新验收前复核，验收结束按实际使用范围清理，不能从旧文档的 PID 推断当前运行状态。

中央推理、客户端执行的架构保持：Codex/App Server 只在中央运行，文件、命令和 Git 由目标 Local Agent 执行，Agent 主动出站连接，客户端不开入站 SSH。简化设备认证不等于完成中央 Worker 的跨操作系统隔离；现有中央 macOS Worker 隔离边界沿用，**Windows 中央 Worker 隔离仍为后续工作**。
