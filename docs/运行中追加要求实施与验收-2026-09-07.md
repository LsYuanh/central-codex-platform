# 运行中追加要求实施与验收

日期：2026-09-07。用户已确认文字追加首版范围。代码整合在 `spikes/local-dev/`，未提交 Git。

## 实现结果

- 运行中按 Enter 或点击“追加要求”向当前 Turn 发送文字；每条收到提交回执后可继续发送下一条。
- 保留独立停止按钮。初始 Turn 提交尚未确认时暂不可停止；运行中追加提交不禁用停止。
- 支持发送中、已接收、失败、结果待核对；失败保留草稿，未知结果通过历史及消息状态核对，禁止自动重发。
- 首版仅追加文字；图片/文件追加和运行配置变更不在范围内。模型、推理设置用于之后正常开始的新轮。
- `conversation.turn.steer` → 中央 `turn/steer`，校验用户、来源设备和 expectedTurnId，复用提交记录和消息 ID 去重。
- 只有上游明确拒绝无活动轮、预期轮是最新一轮且正常完成、当前无活动轮、未收到停止请求时，才使用同一消息 ID 自动开始下一轮。
- 停止、失败、旧 Turn ID、正在运行的另一轮、超时和断线均不触发自动续发。
- 同轮用户消息按 marker 精确匹配；旧历史仅在单条用户消息且单条提交时回退到 Turn 匹配。助手流式输出按 item ID 更新，避免追加前后的回复拼接。
- 原 Turn 生命周期和追加提交状态分离，追加失败不会把正在运行的任务标成结束。

追加不会撤销既有修改，也不保证立刻截断正在生成的内容或正在执行的命令。真实 UI 验收中，原回复继续输出部分内容后，再按追加要求产生新回复；两段回复分开显示。
