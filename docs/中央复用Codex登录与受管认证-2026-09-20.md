# 中央复用 Codex 登录与受管认证（2026-09-20）

推荐接入方式改为复用中央机当前系统用户的原始 Codex 登录。中央账号库只保存账号身份关联，不再保存该登录的访问令牌或刷新令牌副本。官方 Codex 认证进程负责续期，原生管理器读取落盘后的最新访问令牌，再通过现有受管 stdio 交给网关。独立设备登录与旧副本导入保留为其他选项。

本文记录开发阶段的实现与验收。用户后续已授权部署，中央 0.1.1 已启用本功能，当前运行状态、制品和回退方法见[正式部署记录](中央共享登录正式部署-2026-09-20.md)。下方未验证范围保留开发阶段口径，以上述部署记录补充结果为准。

## 使用方式

1. 使用包含本功能的中央 App，以及支持 `accountUpdatesReady` 的网关运行包。在“模型接入”点击“复用本机 Codex 登录”，已有账号不需要再次浏览器授权。
2. 选中关联账号后启动中央服务。已有服务首次切换账号需要停止再启动，之后令牌热更新不需要重启。
3. 中央管理 App 和其受管服务须运行；Codex 桌面程序可以关闭。停止中央服务后停止续期，下次启动先检查认证。
4. 原始账号被退出、撤销或换成另一账号时，页面提供恢复提示；先在中央机重新登录 Codex，再点击关联入口。不会静默切换到另一个模型账号。

本版固定读取中央系统用户目录 `.codex/auth.json`。不接受页面传入路径，也不继承任意 `CODEX_HOME`；仅存于系统钥匙串或自定义 Codex 目录的登录不在本版接入范围。到期时间仍由上游签发，自动续期不能保证授权永久有效。

## 实现与边界

- schemaVersion 2 关联记录只有来源类型、账号身份和关联时间；旧 schemaVersion 1 导入/独立登录保持兼容。共享来源读取时仍验证私有文件、账号与令牌格式，刷新令牌不进入 gateway/Worker/UI。
- 认证二进制来自已核验并保持文件锁定的运行包。中央按需启动短生命周期官方 `codex-app-server`，固定使用原始 Codex home 和文件认证存储。
- 私有 stdin/stdout 只发送 `initialize`、`initialized` 和 `getAuthStatus`。启动检查取当前 token，到期前请求官方刷新；从原始文件重新读取并核对账号、token 与有效期后才交付网关。任何服务器侧执行/审批请求均拒绝。
- 每 30 秒检查；通常提前 24 小时续期。短期令牌下一次检查按剩余寿命一半调度。临时失败以 60 秒起指数退避、最多 1800 秒间隔，初次失败后最多重试 6 次；明确失效或重试耗尽显示重新登录。
- 进程内互斥及 `.codex/central-auth-owner-v1` 目录锁串行化不同中央配置的认证。该锁不约束外部 Codex 桌面进程，外部更新由官方认证管理器刷新前重读及原生交付前再次核对处理；不声称能锁住第三方写入。
- 单次认证限时 30 秒，停止服务/退出中央 App 时取消；关闭 stdin 后最多等 2 秒，仍不退出则 kill 并 wait 回收。测试覆盖拒不响应 EOF 的进程。异常断电/强杀后的登录恢复遵循官方 Codex 行为；不会自行重放刷新请求。
- 网关仅收到 access token 和相同账号身份，沿用实例、revision、确认回执及现有模型代理 lease。已在运行的模型请求不取消，失败任务不自动重发。
- 原始登录更换账号会拒绝交付。现存网关内存 token 不会因原始文件删除立即被撤销；其停止使用取决于服务停止、到期或上游撤销。
- 旧网关运行包不支持热更新时，页面提示升级运行包，后台不假装已完成自动续期。
- 中央推理、客户端 Local Agent 执行保持不变；认证进程不创建 Thread/Turn，不执行客户端文件、命令或工具。SSH 仅用于开发验收。

## 主要文件

路径相对 `spikes/local-dev/`：

- `apps/central/src-tauri/src/model_shared_login.rs`：共享关联、刷新调度、官方认证子进程及恢复状态。
- `apps/central/src-tauri/src/model_shared_login_tests.rs`：合成进程故障与原始登录显式集成测试。
- `apps/central/src-tauri/src/{model_accounts,model_account_renewal,runtime_package,service,main}.rs`：兼容读取、可信二进制、受管生命周期和原生命令。
- `apps/central/src/{ModelAccounts,App}.tsx`、`service-client.ts`：推荐入口、账号来源与错误恢复。失败选项保留，防止错误提示因自动清空选择而消失。

## 验证

- 中央前端 TypeScript check / Vite build、Rust fmt/check 通过。
- Windows 常规原生测试 75 通过、11 项显式集成默认忽略；macOS 58 通过、6 项默认忽略。macOS 保留原有 config/tls 等 3 条编译警告。
- 两个平台显式进程 QA 均通过：成功读取、拒绝工具审批请求、超长帧、空认证、超时、取消、EOF 退出以及拒不退出时强制回收。
- 中央 Mac 真实现有登录测试通过：完整运行包哈希校验、官方认证接口、临时中央关联、重复关联去重、跨配置锁、启动检查及最新 access token 读取。无令牌输出，不改变正式账号选择。隔离源码目录为 `artifacts/shared-login-qa-20260920-01`。
- 隔离测试完成后，使用既有 CA 校验正式中央 HTTPS `/healthz`，返回 HTTP 200，正式服务持续运行。
- `node scripts/native-account-update-smoke.mjs` 通过：同一模型代理 lease 使用更新后的 token，拒绝过期 token、refresh token、账号切换、旧实例与旧 revision，回执不含凭据。上游为合成 HTTP 服务。
- Windows 调试 Tauri 实际页面已检查推荐卡片、原生账号列表空态和“其他登录方式”展开。没有在此 Windows 客户端关联其个人登录。
- Windows 受限沙箱首次回归触发原有 ACL/DPAPI 目录保护（`CONFIG_STORAGE_UNSAFE`）；正常用户权限下全部通过，没有放宽产品保护。macOS 远程测试曾因 PowerShell 管道尾部 CR 导致 shell 退出码非零，测试本身已通过，后续改用单行 SSH 命令复核。
- 没有强制轮换中央仍有效的真实令牌，也未等待其进入到期窗口。实际上游 refresh token 轮换和新版本正式服务持续运行仍属于部署后验收，不能用合成测试代替。

常规命令在 `spikes/local-dev` 运行：`npm run check --workspace @central-codex-spike/central`、`npm run build --workspace @central-codex-spike/central`、`cargo fmt --all --check`、`cargo test -p central-app --bin central-app --locked`。
