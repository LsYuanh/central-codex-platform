## 本轮实现

### P0 / P2：固定上游与中央运行时

源码依赖、可重复应用补丁和中央启动资料位于现有 `spikes/local-dev/harness/`。
源码缓存和构建产物忽略，不建立另一套产品入口。中央执行仍沿用 App Server stdio。
进程显式 `CODEX_REMOTE_WORKSPACE=1`；初始化必须返回
`yuan-zhou-remote-workspace/1` 标识。网关默认拒绝未返回该标识的 stock runtime，
不提供运行时回退开关。标识是兼容握手，不是独立安全证明；源码负测和 OS 约束另行验收。
固定源码的 25 文件补丁、实际中央构建、运行时负测及 macOS OS 隔离探针均已有证据，
详见 [源码审查与验收](harness-source-audit.md) 和
[中央产物及测试哈希](../spikes/local-dev/harness/verification/central-qa.json)。

网关对 UI 的工作目录、权限、沙箱、配置、工具和执行环境覆盖拒绝；从 Agent hello
取得设备安装 key 与实际工作区根，持久化 Thread 的 user/device/key/workspace/policy 绑定。
每次执行核对当前连接，禁止同名设备或新工作区继承旧 Thread 的执行权。
Agent 再次校验服务端附带绑定；动态工具参数不能自带或替换此绑定。

设备响应与输出同时校验请求 ID、设备 ID 和原连接 socket；重复 hello 不能换身份。
超时发取消请求，未收到可靠终态时返回 `RESULT_UNKNOWN`；断线也不标记可自动重试。
App Server 请求增加 60 秒响应期限，Turn 提交仍保留既有未知提交/历史核对机制。
取消请求和执行真正结束保持分离，审批等待中的停止不会在之后批准时重新派发。

### P1：现有 UI 适配边界

`gateway-ui-events.ts` 集中平台事件、审批、执行、连接和保存类型及转换；
现有 App 移除被替代的设备事件解析，保留原生 Thread/Turn 历史与计时逻辑。
重复开始、迟到输出、终态后事件和断线不再重置日志或复活已结束操作。
卡片区分中央已派发与已收到客户端输出，单独展示超时、拒绝、离线、未知状态。
工作区新增实际 Git diff 入口，并核验响应来源和格式。
详见 [UI 实施记录](harness-ui-implementation.md)。

### P3：客户端代码修改闭环

新增 `workspace/context/search/read_text/git_status/git_diff/apply_patch`。
规则和环境来自客户端；搜索/读取有明确大小、数量、时间和分页上限。
补丁文本能力提取自固定 Codex `apply-patch`，不是重新实现一套补丁语法；
Local Agent 保留路径、版本、权限和真实文件提交职责。没有安装客户端 Codex。

补丁流程为客户端 dry run → 返回补丁 hash 与每路径 SHA-256 / missing 前提 →
UI 展示设备、工作区、完整补丁及版本 → 单次批准 → 客户端重新验证并提交。
每文件读回校验。多文件操作不是事务，明确返回已改路径及 partial/unknown，
不承诺自动回滚、不自动重放。Git diff 来自真实客户端 Git 输出。
失败命令保留既有错误文本和 `ok:false`，同时附真实 exitCode/stdout/stderr/truncated；
不从错误字符串猜测退出码。
详见 [Agent 实施与边界](harness-agent-implementation.md)。

## 复用与兼容结论

| 能力 | 本期处理 | 依据与保留边界 |
| --- | --- | --- |
| Agent 循环、模型、上下文、Thread/Turn | 继续上游原生 | 平台不实现第二个推理循环或完整会话真相 |
| Turn steer / interrupt | 复用原生 | 保留跨网提交 ID、结果未知核对及客户端进程树取消 |
| 补丁语法、匹配、换行重建 | 固定上游文本组件 | Local Agent 适配文件快照、版本、权限及提交；许可单独保留 |
| UI 设备执行状态 | 集中转换并移除页面重复实现 | 原生 Turn、设备执行、文件保存是独立状态域 |
| 内置本机工具、MCP、插件、子代理 | 未适配入口暂禁用 | 名字相似不能视为已满足设备/工作区继承 |
| 原生图片生成 | 远端模式暂禁用 | 旧输出查看/保存和内联附件输入保留；UI 明示限制 |
| 用户/设备关联、AgentRPC、提交可靠性 | 平台保留 | 上游单运行时不能替代跨设备平台归属 |
| 历史 | 加法元数据兼容 | 原生 rollout 不改格式；旧设备工具通过 `codexia.workspace` 兼容路由 |

旧 Thread 动态工具表没有新名字时，使用保留的 `device_exec` broker 保留程序
`codexia.workspace`（context/search/read_text/git_status/git_diff/apply_patch），
它映射到同一处理器且绝不启动同名可执行程序。旧文件输出 `codexia.files` 暂保留。
新旧会话真实恢复与迁移验收完成之前，不删除这些有明确历史依赖的兼容入口。

## 尚需明确的验收边界

P5 身份目前仍是可信局域网 userId/deviceId，不是正式认证。Agent 路径检查与 exec 初始
cwd 约束不是客户端 OS 沙箱：Shell 可访问其 OS 账号允许的绝对路径。附件/输出仍保留
既有可信局域网绝对路径范围，不伪称严格工作区隔离。中央 OS worker 权限、专项入口
负测及真实模型读规则→搜索→修改→diff→测试已有上述证据；完整上游测试、旧会话迁移、
独立 macOS 客户端及正式安装升级仍未验收，不应由本次隔离测试推断通过。
