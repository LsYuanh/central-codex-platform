# 开源 Codex Harness 改造计划

日期：2026-09-09  
状态：方案草案，待确认实施范围  
适用项目：远舟 / central-codex-platform  
实施主目录：`spikes/local-dev/`

## 1. 目标与本次范围

保留当前 Tauri + React 界面和 Local Agent，以开源 Codex harness 作为中央 Agent 引擎，定向改造工作区访问和工具执行边界，使用户工作区操作只能在任务绑定的客户端执行。

本次仅编写计划，不修改应用代码、不创建 Codex fork、不部署网关、不迁移历史数据。确认实施范围后按阶段推进。

核心复用原则：**Codex harness 已有且经过验证优于当前项目的能力，直接采用其成熟实现；现有项目只保留必要的平台功能和远端适配，避免长期维护重复方案。**

预期成果：

- 当前界面的布局、主题、输入和会话交互继续可用。
- 模型调用、Agent 循环、上下文和原生任务能力优先由 Codex 承担。
- 客户端执行由运行时代码和 Agent 权限共同保证，不仅依赖提示词。
- 设备环境、文件、修改记录、命令输出与界面展示对应同一个客户端工作区。
- 已有会话、附件、输出文件、设置和安装版使用方式具有明确兼容方案。
- Codex 自定义修改集中在必要接口，能够测试、升级和回退。

## 2. 架构边界

```text
现有 Tauri + React UI
    │ 平台功能接口、状态与事件
    ▼
中央平台网关
    ├── 用户 / Thread / Device / Workspace 归属校验
    ├── Worker 管理、权限、配额、审计
    ├── Codex 协议适配
    └── Device Broker
          ▲                         │
          │ 工具请求与结果            │ AgentRPC
中央 Codex App Server / harness      ▼
    ├── 模型服务调用             客户端 Local Agent
    ├── Agent 循环                  ├── 文件与搜索
    ├── 上下文与 Thread / Turn      ├── 补丁与 Git
    └── 远端工作区执行接口            └── Shell 与进程
```

Local Agent 主动出站连接中央网关。图中请求路由方向不代表中央机主动建立客户端入站连接。

必须保持：

1. Codex 和 App Server 仅在中央机运行；客户端不安装或启动本地 Codex、CLI、helper、App Server。
2. 中央机调用模型服务并编排任务；harness 开源不等于模型权重开源或模型在中央机本地推理。
3. 用户工作区的文件、命令、Git 和系统探测统一由目标客户端 Local Agent 执行。
4. 设备离线、身份变化、权限拒绝或能力不支持时明确失败，不回退为中央执行。
5. 中央机可维护 Codex 自身配置、会话及平台运行数据；这些数据与用户工作区操作明确区分。
6. 客户端不开放入站 SSH；SSH 仅作为开发和诊断中央机的手段。
7. 保持现有产品入口，不建立第二套 UI 或平行产品工程。

## 3. 当前基线与能力归属

以下基于现有代码和交接记录，不代表本次重新完成了运行验收。P0 必须记录部署版本并补充基线验证。

| 领域 | 当前基础 | 目标处理 |
|---|---|---|
| 桌面界面 | 会话、主题、输入、附件、输出、设置、执行卡片 | 保留并适配数据，按实际缺口补充界面 |
| UI 服务接口 | `CodexiaGatewayAdapter` 与 `PlatformGatewayClient` | 在现有边界内增强类型和事件转换 |
| 模型与 Agent 核心 | 中央 App Server | 继续使用 Codex，避免自建第二套 Agent 循环 |
| 会话与任务 | 原生 Thread / Turn 加平台状态、提交记录 | 原生状态优先；保留跨设备关联与提交可靠性处理 |
| 设备工具 | `device_*` → 网关 → Local Agent | 保留真实链路，逐步接入运行时强制执行接口 |
| 客户端文件 | 读取、文本写入、复制、发布、附件与生成结果保存 | 复用现有实现，补齐搜索、补丁、版本冲突和变更展示 |
| 命令执行 | 流式输出、超时、取消与进程树处理 | 与 Codex 生命周期衔接，保留跨设备执行保障 |
| 生命周期 | Tauri 自动管理 Local Agent、安装包内置 Agent | 保留，并回归验证启动、关闭、重启和配置切换 |
| 平台身份 | 可信局域网临时用户 / 设备标识及路由 | 正式多用户使用前补齐认证、授权和 Worker 隔离 |

## 4. 成熟能力复用与替换规则

### 4.1 判定流程

每项候选能力都记录：当前行为、Codex 固定版本对应模块、接口约束、对比结果、替换结论和回退方式。

不能只根据功能名称或官方界面表现认定开源实现可直接复用。固定版本源码、编译产物和真实链路行为是验收依据。

| 判定 | 处理方式 | 示例 |
|---|---|---|
| Codex 已覆盖，行为更完整且满足边界 | 直接采用，迁移后移除重复实现 | 可替代平台推断的原生任务终态 |
| Codex 逻辑成熟，但依赖本机执行 | 保留成熟逻辑，适配远端执行接口 | 补丁、命令执行流程和对应事件，具体拆分待源码审查 |
| Codex 只覆盖单进程或单主机部分 | 使用原生机制，保留跨设备补充 | Turn 中断与客户端进程树取消 |
| Codex 不覆盖平台需求 | 保留或自研 | 用户认证、设备归属、租户授权、配额、审计 |
| 优势或兼容性尚不明确 | 先验证，不提前替换 | 历史持久化、断线恢复、动态工具变更 |

### 4.2 替换约束

- 使用统一的用户场景比较正常、失败、超时、中断、断线和恢复行为。
- Codex 的 Thread / Turn 状态作为原生任务状态来源；平台维护设备执行、提交确认和保存状态，不混成一个状态。
- 平台元数据不重复保存一套可与上游相互冲突的完整会话真相；历史缓存和兼容记录明确来源与更新规则。
- 不能因为上游有“中断”就移除 Agent 的进程取消；不能因为上游有“审批”就取消客户端权限校验。
- 迁移完成并通过回归后清理旧实现；兼容入口注明适用历史数据、退出条件和移除时机。
- 不为了复用本地沙箱而在客户端引入 Codex；可移植的独立执行组件另行评估。

## 5. 分阶段实施

### P0：固定基线与源码能力审查

任务：

- [ ] 记录当前中央 Codex/App Server 版本、启动配置、网关版本、客户端和 Agent 版本。
- [ ] 保存现有未提交改动清单，检查 stash，确保后续改造不覆盖用户工作。
- [ ] 为上游 Codex 固定 tag/commit，归档 LICENSE、NOTICE 和第三方组件信息。
- [ ] 从固定版本生成并保存 App Server 协议 Schema，记录实验性接口与兼容范围。
- [ ] 审查工具注册、调用分发、文件/搜索/补丁/命令/Git、规则加载、环境探测和相关插件入口。
- [ ] 审查子任务是否继承设备、工作区和执行策略，记录不能覆盖的入口。
- [ ] 明确哪些是稳定配置能力、哪些需要源码修改，避免可配置功能重复打补丁。
- [ ] 完成逐项“直接复用 / 远端适配 / 平台保留 / 暂不替换”对照表。
- [ ] 确定 fork 源码依赖组织方式；集成现有构建流程，不形成第二个产品入口。

交付物：版本基线、能力对照表、执行入口清单、最小 fork 修改清单、兼容与回退设计。

验收门槛：能从固定源码构建中央运行时；所有计划替换项有源码依据。阶段结束后才能承诺具体模块和工期。

### P1：整理 UI 适配边界

任务：

- [ ] 保留现有页面结构和样式，从 `App.tsx` 按功能逐步拆出连接、会话、执行和审批状态处理。
- [ ] 在现有适配器中定义明确的会话、消息、执行记录、审批和输出类型。
- [ ] 将原始 App Server 协议解析集中到适配边界，逐步减少页面直接处理 `AppServerMessage`。
- [ ] 为中央连接、设备在线、Turn 状态、客户端执行状态、文件保存状态分别建模。
- [ ] 复用已有 Thread 隔离、草稿和提交确认机制，检查事件重复、乱序和重连后的状态核对。
- [ ] 不支持的能力在界面明确禁用或解释，避免无限 loading。

交付物：稳定的 UI 功能接口及事件映射，已有页面继续使用。

验收门槛：现有对话、追加、停止、附件、输出、设置和多会话行为无回退；前端检查、构建和 Tauri 页面验证通过。

### P2：建立强制远端执行机制

任务：

- [ ] 在中央运行时建立显式远端工作区模式，绑定用户、设备、工作区及执行策略。
- [ ] 定义执行接口、能力协商、错误类型、调用标识、超时和取消契约；扩展现有 AgentRPC。
- [ ] 中央网关校验归属后路由，Local Agent 再次校验工作区、路径和实际权限。
- [ ] 所有受支持的用户工作区入口转到 Agent；暂未适配的入口在远端模式中禁用或拒绝。
- [ ] 对内置工具、无需审批读取、Git/环境探测和规则加载做覆盖审查，不能仅拦截审批事件。
- [ ] 插件和子任务无法继承远端边界时暂不开放相关能力，不能允许绕过。
- [ ] 设备离线、超时、拒绝、重连后身份变化均有明确结果，不产生中央执行回退。
- [ ] 将 Codex 自身运行数据与用户工作区访问区分，结合中央 Worker 的操作系统权限进行隔离。

交付物：最小 Codex fork 补丁、远端执行适配器、AgentRPC 扩展和负向验证证据。

验收门槛：中央与客户端放置内容不同的测试标记，确认文件读取、命令和系统信息来自客户端；刻意请求中央内置入口时无法绕过。中央运行数据写入允许名单需单独核对。

### P3：打通代码修改完整闭环

任务：

- [ ] 从客户端取得操作系统、Shell、工作区和适用的项目规则。
- [ ] 补齐客户端目录搜索、文本搜索和分页读取。
- [ ] 按 P0 结论复用 Codex 补丁能力，并在客户端完成文件访问、版本冲突检查和实际修改。
- [ ] 明确多文件补丁的部分失败与恢复语义，不宣称未实现的全量事务或自动回滚。
- [ ] 取得客户端 Git 状态和实际 diff，展示到现有工作区/变更界面。
- [ ] 衔接命令 stdout/stderr、退出码、超时、中断和进程清理。
- [ ] 审批展示真实目标设备、路径、命令和修改内容；批准只授权对应客户端操作。
- [ ] 审批等待期间文件变化时重新校验，避免旧审批应用到不同内容。
- [ ] 保持已有附件与生成结果保存链路，继续核对客户端真实路径和文件校验值。

首期主验收场景：

> 选择客户端项目 → 读取规则 → 搜索代码 → 修改文件 → 展示实际 diff → 运行测试 → 展示真实输出与退出码。

故障验收：操作前离线、执行中断线、权限拒绝、审批后文件变化、命令超时、用户停止、结果回传丢失。

验收门槛：真实中央机与 Windows 客户端通过；macOS 客户端在具备独立环境后执行对应验证，未验证平台单独记录。

### P4：替换重复实现与迁移历史

任务：

- [ ] 按能力对照表逐项接管成熟的 Codex 任务、事件和会话能力。
- [ ] 保留平台用户/设备关联、客户端输出元数据和跨网络提交可靠性处理。
- [ ] 使用原生任务标识关联客户端执行；停止完成时区分“请求已接收”和“客户端进程已退出”。
- [ ] 验证旧 Thread 动态工具、旧提交记录、附件、生成结果和归档数据的兼容。
- [ ] 为数据格式变更增加版本及迁移记录，迁移前保留可恢复备份。
- [ ] 通过回归后删除重复逻辑；确需保留的旧入口明确退出条件。
- [ ] 确认回退到前一安全版本时历史可读取，避免依赖不可逆格式转换。

验收门槛：新旧会话可恢复，未知提交不会盲目重发，重复写入不产生额外副作用；旧逻辑清理有功能替代和验证记录。

### P5：正式多用户与发布

任务：

- [ ] 将可信局域网临时身份替换为可验证的平台登录和设备身份。
- [ ] 用户不能读取、续聊或执行其他用户的 Thread、设备和工作区。
- [ ] 明确每用户 Worker/运行目录/凭据访问边界；独立进程或 `CODEX_HOME` 本身不作为完整隔离证明。
- [ ] 完成认证传输、设备配对与吊销、权限、审计、并发配额及故障恢复。
- [ ] 根据既有部署和授权决策确认模型凭据与用量管理方案。
- [ ] 固定 Codex fork 产物、协议和 Agent 最低兼容版本；不兼容时明确拒绝或降级可用能力。
- [ ] 构建桌面安装包，验证 Agent 生命周期、配置保留、升级与回退。
- [ ] 同步运行文档，并按发布范围完成签名、更新和分发验收。

验收门槛：正式身份下两用户/两设备的隔离与真实执行通过；不能用修改 UI 的 `userId` 冒充其他用户。P5 完成前不宣称生产级多用户平台已完成。

## 6. 验证与发布策略

| 改动范围 | 最小充分验证 |
|---|---|
| UI / 适配器 | TypeScript check、Vite build、Tauri 页面、相关状态回归 |
| Tauri | `cargo fmt --check`、`cargo check -p desktop-spike`、对应原生路径验证 |
| Local Agent | Cargo check/test、设备 smoke、真实客户端结果核验 |
| 网关 | TypeScript build、协议 smoke、真实中央连接 |
| Codex fork | 固定上游要求的构建与专项测试、执行边界负向测试、真实远端闭环 |
| 生命周期 | 客户端启动/关闭对应 Agent 注册/注销，执行中退出后无孤儿进程 |
| 多用户 | 交叉 Thread/Device/Workspace 访问拒绝，事件和输出不串用户 |
| 历史迁移 | 旧会话、附件、输出、归档恢复以及回退可读性 |

- Fake Central 仅用于协议回归，不能替代真实中央验收。
- 写入和命令执行结果未知时先核对状态，不自动重放有副作用操作。
- 先在隔离测试端口和独立测试设备验证，再更新正式服务。
- 上游版本、网关、Agent 与协议兼容组合形成发布记录。
- 回退只允许回到满足客户端执行边界的版本，不能用中央本地执行作为兜底。
- 不同时启动争用同一 Cargo 构建锁的重复构建。

## 7. 首期范围与暂缓项

首期建议批准 P0—P3：能力审查、UI 适配边界、运行时强制远端执行，以及完整代码修改闭环。

暂缓到有明确需求或前置验证后：

- 交互式 PTY 终端、长期后台进程和端口转发。
- 多设备之间迁移同一个活动任务。
- 未审查的插件或工具直接进入远端工作区模式。
- 与当前界面无关的完整官方桌面功能复刻。

P4 按已验证替换项分批推进；P5 是正式多用户发布前置要求。P0 结束后再依据实际源码耦合、兼容范围和验证环境制定工期。
