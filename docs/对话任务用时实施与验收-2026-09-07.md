## 2026-09-14 处理过程展开与收起

按用户确认的两张参考图，在现有对话区增加每轮独立的展开/收起功能。以下规则优先于后文的旧版展示说明：

- 用时和箭头位于本轮第一条服务端消息上方，下面保留细分隔线。点击该行切换处理过程；运行中默认展开，完成后默认收起，手动切换不会被每秒时钟刷新打断。
- 收起只隐藏明确标记的过程内容；最终结果、文件/图片卡片、用户追加要求和没有类型标记的旧回复保持可见。
- 展开按消息/事件顺序显示服务端返回的思考摘要、过程说明、工具摘要和本机执行卡片。运行中保留旋转动效；断线显示待核对状态，失败显示失败状态及未成功操作提示。
- 识别 `agentMessage.phase` 的 `commentary` / `final_answer`，合并 `item/started`、`item/completed`、推理摘要增量和计划增量；完整结束事件校正流式文本，避免结束后重复追加。
- 思考摘要仅展示服务端公开返回的 `summary`，不读取或替代为原始推理 `content`。服务端没返回的摘要不补造。旧历史没有 phase 时不猜测消息类型。
- 历史恢复保留摘要、阶段和工具摘要。详细本机日志仍沿用现有运行时记录，服务器历史没有保存的日志不能凭空恢复；附件按所属 Turn 分组，即使延迟到达也不会落入下一轮。

## 展示与计时规则

- 每轮任务运行时在输入框上方显示「已用时」，每秒更新；完成后在该轮最后一条助手回复前显示「用时 1分 55秒」和细分隔线。
- 同轮追加要求不重置计时；失败、主动停止显示相应状态和已记录的用时。没有助手输出时仍可显示结束记录。
- 按 Thread ID 和 Turn ID 关联，后台任务不会串到当前对话。历史恢复保留消息的 Turn ID，每轮只显示一次用时。
- 优先使用协议明确提供的毫秒时长或服务器开始/结束时间对；缺少协议时间时，记录客户端收到开始和结束事件之间的经过时间。服务器时间与客户端时钟不混算。这是任务经过时间，包含等待与工具执行，不是模型计算时间。
- 本地按网关地址、用户身份隔离缓存，保存最近 2000 条结束记录及待核对记录；刷新或重启后可恢复已记录的时长。存储失败不会阻塞对话，但此时无法保证下次恢复。
- 未记录时间的旧对话不补造用时。离线期间结束且服务器也没有时间数据时，显示「用时未记录」；状态尚未核实时显示「连接中断，用时待核对」。不以重新打开页面的时间充当任务结束时间。
- 缓存只保存在本设备，不提供跨设备时长同步。已有安装包需重新构建后才包含此功能。
