## 2. 网关契约

所有下列接口使用 JSON POST。管理接口拒绝设备令牌，包括归属于管理员用户的设备令牌；设备身份始终只有普通用户权限。既有设备撤销自身、退出自身的兼容行为保留，不能操作同用户的其他设备或其他用户设备。

| 路由 | 请求 | 返回 `data` |
|---|---|---|
| `/auth/admin/login` | `{username,password}` | 既有登录结果，仅允许密码验证通过的管理员 |
| `/auth/admin/users` | `{}` | `{users:[PublicUser]}` |
| `/auth/admin/devices` | `{userId?}` | `{devices:[PublicDevice]}` |
| `/auth/admin/user/create-pairing` | `{requestId,username}` | 新的公开用户对象，`loginMode:"pairing-only"` |
| `/auth/admin/user/disable` | `{userId,requestId?}` | `{disabled:true}` |
| `/auth/admin/pair-code` | `{userId,requestId?}` | `{authMode:"device-token-v1",code,expiresAt,expiresIn:300}` |
| `/auth/device/revoke` | `{deviceId,requestId?}` | `{revoked:true}` |
| `/auth/logout` | `{}` | `{loggedOut:true}` |

`PublicUser` 包含 `id,username,role,disabled,loginMode`，用户列表另外包含 `online:boolean,lastSeenAt:number|null`。旧密码用户无需迁移，缺少 `authType` 的旧持久记录继续按密码用户读取；新配对用户持久记录为 `authType:"pairing-only"`，不得包含 `salt` 或 `passwordHash`。该用户密码登录始终失败，但仍执行 dummy scrypt 和固定长度比较。

设备列表公开字段为 `id,userId,name,revoked,createdAt,authMode,online,lastSeenAt`。旧网关 API 为已有客户端保留 `deviceKey`，中央原生桥过滤该字段，不向中央 UI 返回设备密钥、令牌或令牌哈希。

在线状态由 `PlatformAuth.setDevicePresence((deviceId,userId)=>({online,lastSeenAt}))` 注入，网关读取当前 Agent 连接。没有读者时返回离线和未知时间；持久注册记录不代表在线。已撤销设备或已停用用户不能被列为在线。用户列表的在线信息从所属设备聚合。

### 幂等与配对码

- 新建配对用户必须提供 `requestId`；停用、配对码、撤销允许省略，以兼容原有客户端。已改管理路由严格拒绝未知字段和查询参数。
- 幂等按管理员会话、请求 ID、规范化操作及载荷绑定；先预留 pending 条目再执行，避免并发相同请求创建两次。最多 1000 条，TTL 为 5 分钟，只保存在内存。
- 相同 ID 的不同载荷返回 `REQUEST_ID_CONFLICT`。不会跨网关重启承诺幂等；原生/UI 对不确定结果要求读回核对，不能自动以新 ID 重试修改。
- 配对码有效期 5 分钟，只能兑换一次。同管理员会话对同用户重发时，先撤销该会话此前未消费的码。已消费或被重发替代的码，其旧幂等请求返回 `REQUEST_EXPIRED`，不重新生成或复活旧码。
- 发行者登出、会话过期或停用、目标用户停用都会使配对码失效。设备撤销和用户停用会立即撤销鉴权并关闭已跟踪的连接，保留持久记录。
- 新配对用户创建的重复用户名检查和提交之间没有异步间隙；既有密码创建在 scrypt 返回后仍重新检查用户名。

### 管理员会话

`/auth/admin/login` 使用独立 `scope:"central-admin"`。只有密码验证通过且账号确为管理员后，才替换同用户先前的该 scope 会话。普通 `/auth/login` 会话保留；刷新沿用原会话并保留 scope。请求体不能传入 scope。这样 App 退出或崩溃后丢失内存令牌，不会因反复重新登录积累十个管理会话而无法继续管理。该接口仍受既有密码登录限速约束。
