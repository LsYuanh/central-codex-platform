## 问题与结果

原对话 `01a06531-5ad7-7852-8d5f-bd105f1b7e4d` 的 App Server 历史实际包含两个已完成的 `imageGeneration` 项，内容是内联 PNG Base64；原 UI 只恢复文本，没有接入图片输出项。另一个问题是客户端命令 cwd 的绝对路径被旧工作区规则拒绝，且缺少结构化写入、保存校验与输出卡片。

现在网关消费原生图片结果，分块发给来源客户端 Agent；Agent 保存到系统下载目录的 `Codexia` 子目录并回读校验。UI 根据元数据经本机 IPC 加载预览，实时消息和恢复历史均展示图片、保存状态与本机路径。旧历史自动补齐，失败可以重试。中央模型新增文本写入、复制、发布、输出目录及输出列表工具；旧对话通过保留的设备工具兼容入口使用相同实现。

中央只推理和路由，客户端系统操作始终由 Local Agent 执行。未加入客户端入站 SSH、本地 Codex 或额外中央原文件仓库。App Server 自己仍可能保留生成结果；原生 `savedPath` 不被当作客户端路径，也不被此网关读入。

可信局域网模式允许客户端本机绝对路径，受当前系统用户权限限制，不提升操作系统权限。相对路径仍受 workspace 边界约束。结构化覆盖要求版本，默认图片另存；普通命令仍按其本身语义执行。文本单次 256 KiB，图片/复制/发布 20 MiB，图片解码沿用 8192×8192 / 1600 万像素限制；单块 256 KiB，写入最多并发 4 个且共预留 80 MiB，空闲 60 秒过期。图片保存 45 秒后不再开始下一次写请求，现有有超时的 RPC 和清理请求完成后回传终态。

本轮 Windows 客户端与 macOS 中央链路已验证；macOS 客户端打包、正式认证、WSS/mTLS 和生产权限策略不属于本轮已验证项。
