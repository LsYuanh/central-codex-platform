# 客户端统一配置实施与验收

日期：2026-09-03。适用目录：`spikes/local-dev/`。

## 范围与结果

用户确认上一阶段 P0 验收完成，并同意推进统一连接及本机工作区配置。本轮在原设置页增加
网关地址、本机目录输入/选择、保存并应用、实际配置和环境覆盖提示。UI 与 Agent 由同一份
配置派生连接地址；文件浏览及相对命令默认目录使用 Agent 的真实工作区，客户端路径不再
作为中央模式的 App Server cwd 发送。

配置使用 Tauri 应用配置目录中的 `desktop-runtime-v1.json`，Windows 实测为
`%APPDATA%/com.centralcodex.localspike/desktop-runtime-v1.json`。主题及模型相关偏好沿用原存储。
首次升级可迁移旧 UI 网关地址，旧 Thread cwd 不自动成为本机工作区。

## 生效与恢复

- 点击“保存并应用”后校验地址和目录，向旧 Agent 请求短暂暂停接收新任务，再重建进程及附件 IPC。
- 原子写入配置失败或新 Agent 启动失败时恢复旧 Agent；无效目录在关闭旧进程之前拒绝。
- Agent 已异常退出时可通过同一按钮恢复；损坏配置/不可用 IPC 会显示错误并保留编辑入口。
- UI 阻止已知正在运行的 Turn、未知提交结果、附件准备和输出保存期间切换；Agent 再次检查
  在途命令及未完成传输。暂停接收请求最多 10 秒，避免响应丢失后永久拒绝任务。
- `CODEXIA_GATEWAY_AGENT_URL` 同时影响 UI 与 Agent；工作区、可执行文件覆盖保留并显示来源。
  移除环境变量后需重启客户端。环境覆盖路由和用户标识保持由 Rust 测试覆盖。
- 新地址不可达时配置可保存，中央连接失败显示明确终态和重试入口；“Agent 进程已启动”
  与“设备在线”分别展示。

本轮未修改或重启中央网关；系统文件/命令仍经真实中央 Device Broker 路由到客户端 Agent。

## 文件入口

- `apps/desktop/src/App.tsx`：启动加载、旧地址迁移、任务状态保护、应用后重连、中央 cwd 边界。
- `apps/desktop/src/runtime-settings.tsx`、`styles.css`：现有设置页中的统一配置表单。
- `apps/desktop/src/platform-gateway-client.ts`：默认设备身份解析和关闭后迟到连接保护。
- `apps/desktop/src-tauri/src/main.rs`、`runtime.rs`、`Cargo.toml`：配置存储、环境覆盖、进程/IPC 管理及回归测试。
- `crates/local-agent/src/main.rs`、`runtime.rs`、`attachments.rs`、`outputs.rs`：在途操作保护和真实工作区身份信息。
- `Cargo.lock`、README、AGENTRPC 和交接文档：依赖记录及运行说明。
