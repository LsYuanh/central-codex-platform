# 中央管理 App：首版 UI 与验收

日期：2026-09-10。用户已确认开始中央端 UI，本批落地独立入口、首次配置与运行概览。完整中央管理产品仍在开发，不能据此宣布 P1 服务管理或安装交付已完成。

后续进展：原生配置保存与基础运行检查已在 Windows 接通并完成独立 App 实测，见 [原生配置与检查验收](中央管理App-原生配置与检查验收-2026-09-10.md)。下文描述首版 UI 时点，保留作历史记录。

## 已实现

- `spikes/local-dev/apps/central`：独立 React + Tauri 应用，标识 `com.yuanzhou.central`，开发端口 `127.0.0.1:1422`。沿用现有工作客户端的视觉语言和 `UiIcon` 组件。
- 运行概览：配置入口、网关/模型代理/用户进程状态、在线设备与任务指标、接入准备列表。没有状态来源的数字显示 `—`；未接通的启停按钮禁用并说明原因。
- 三步首次配置：中央数据目录、监听 IP/端口与客户端 WSS 地址、既定“本机已有 Codex 登录”来源及检查说明。提供基本格式校验，保存失败保留输入，保存成功有明确提示。
- 草稿保存在 `yuanzhou.central.setup-draft.v1`，重新打开能恢复，损坏或不可访问的存储显示恢复提示。这里只存非秘密字段，浏览器与桌面分别保存；不构造或提交有效 `CentralConfig`。
- 两个原生命令：`central_ui_context` 返回本机平台、独立应用数据路径与运行管理未接通状态；`central_choose_directory` 打开本机目录选择器。原生信息读取有超时与重试，选择器取消后可继续操作。
- 用户与设备、模型接入、设置与诊断保留导航和准确的未接入说明，没有虚构记录或模拟登录。

## 文件与运行

前端主要文件为 `apps/central/src/App.tsx`、`styles.css`、`setup-draft.ts`、`native.ts`；原生壳位于 `apps/central/src-tauri`。根 npm/Cargo workspace 已登记，依赖锁已更新；原有工作客户端与网关入口保留。

在 `spikes/local-dev` 运行：

```powershell
npm run dev:central-app
# 或仅启动浏览器 UI；不要与上一个命令同时运行
npm run dev:central-ui
```

浏览器预览只支持草稿操作，目录选择和本机应用信息需要桌面 App。原生窗口已实际启动供查看；当前关闭窗口只关闭管理 UI，因为还没有受管中央服务。
