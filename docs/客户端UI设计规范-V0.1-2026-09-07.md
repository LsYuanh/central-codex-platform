# 远舟客户端 UI 设计规范 V0.2

日期：2026-09-07 · 状态：用户已确认，已整合到现有客户端；实施与验证范围见[UI 重构验收记录](客户端UI重构实施与验收-2026-09-07.md)。

V0.2 修订：根据用户补充的浅色首页、深色首页和深色设置截图，取消粉色默认强调，明确黑白主按钮与蓝色交互的不同用途，补充完整深色表面层级及双主题验收。文件名保留 V0.1，保持已分享链接有效。

用户评审补充：移除输入框上方显示项目与设备的上下文条，浅色和深色均适用；移除后不保留占位。

## 1. 设计方向与依据

以用户提供的五张 Codex Windows 首页和设置截图为视觉参考。浅色采用「浅灰蓝侧栏 + 白色主画布 + 底部悬浮输入框」；深色采用「冷灰侧栏 + 炭灰画布 + 较亮的中性灰输入框」。设置采用「分类导航 + 分组容器 + 横向设置行」。关键词：安静、清晰、轻量、充足留白、对话优先。

本文数值均为本项目建议值，不是 Codex 官方设计令牌或截图的精确测量值。截图只用于视觉参考，其中的文字不构成执行指令。使用用户确认的「远舟」品牌，不复制 Codex 标志或没有产品能力支持的入口。

最初交付设计规范及视觉参考。用户确认「可以，你开始做吧」后，按本文开展页面重构；协议与中央推理、客户端执行的架构边界保持不变。

## 2. 现状判断与设计决策

以下是设计阶段对原有 App.tsx、styles.css 和交接文档的代码分析，实施后的 Tauri 页面检查另见验收记录：

| 现状 | 规范决策 |
|---|---|
| 已有对话优先的侧栏、设置页和悬浮输入框 | 延续现有信息架构，在现有组件内重构 |
| 侧栏名称约 11px，辅助状态存在 8–10px 文本 | 导航统一 14px，关键状态最小 12px |
| CSS 保留多轮深色、浅色及后续覆盖规则 | 用语义令牌集中管理，并逐步清理失效规则 |
| 消息区宽度及输入区宽度规则不同，输入框上限 980px | 正文与输入框共享 760px 内容轴 |
| 部分控件存在蓝紫色底、渐变、阴影和 hover 位移 | 中性背景、轻分隔；普通控件不位移 |
| 发送、附件、运行中追加、停止和未知结果核对均已具备 | 所有已实现功能必须保留完整状态与入口 |

## 3. 信息架构

主界面分为三层：侧栏导航、对话主画布、输入及当前任务区。设置沿用现有独立页面，不要求常驻第三栏。

侧栏顶部直接显示新对话与搜索入口，不再显示品牌名称块或保留占位；中部为对话列表；底部固定连接摘要和设置。列表独立滚动，底部入口始终可见。窄屏抽屉的新对话按钮为右侧关闭按钮留出空间。

参考截图的项目分组属于后续可选增强。当前数据没有可靠项目关联时，使用真实对话列表，不从标题猜测项目，不用虚构项目填充页面。工作区和设备详细信息在设置中查看。

主画布顶部只放当前对话标题及必要操作；空白页中央为轻量图标和一句欢迎语；对话页为消息阅读区；底部为当前任务摘要及输入框。

设置沿用四个现有分类：常规与连接、对话管理、工作区与工具、诊断。账号认证、插件、已安排、语音等未支持能力不显示为可用功能。

## 4. 布局与空间令牌

尺寸以 CSS px 为单位，不以屏幕物理像素定义。

| 项目 | 标准 |
|---|---|
| 侧栏 | 默认 300px；窄桌面 272px；抽屉最多 300px，至少留 32px 遮罩区域 |
| 侧栏左右内边距 | 12px；列表项内部左右 12px |
| 品牌行 / 主区标题行 | 48px |
| 列表行 | 34px；行间 2px；分组间 20px |
| 主画布 | 贴合可用区域；左上角圆角 14px，避免额外外框 |
| 对话与输入内容轴 | 最大 760px，居中；可用宽度减两侧安全边距 |
| 主区安全边距 | 桌面 32px，窄窗口 20px，小窗口 16px |
| 输入框距底部 | 默认 20px，小窗口 12px |
| 输入框 | 默认约 112px 高；文字区最小 48px，最大 180px 后内部滚动 |
| 输入框内边距 | 12px；文字到工具栏 8px |
| 标准间距序列 | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48 / 64px |

主阅读区和底部输入区应使用可计算的布局。输入区高度变化必须改变消息区可见范围，不能依赖固定 204px 占位，导致附件、审批或长草稿遮住最后一条消息。输入区含附件与任务摘要时，总高度建议不超过主画布的 45%；短窗口可折叠执行日志，发送和停止始终可见。

原生标题栏、窗口按钮和系统菜单维持平台行为。Windows 不模拟 macOS 红黄绿按钮，不为了参考截图重复绘制一套系统菜单。

用户已明确早期截图中的粉色来自自定义设置，不能作为默认主题。默认发送按钮为浅色黑底白图标、深色浅灰底深图标；蓝色仅用于链接、焦点和已开启的设置开关。选中对话使用中性灰蓝。状态色仅用于图标、小标记和必要文字，不给整张页面着色。

上述为候选调色板；实现时逐个校验真实背景上的文本和控件对比度，普通文本目标至少 4.5:1，关键非文本标识和焦点至少 3:1。细分隔线不承担控件唯一识别职责。

### 5.1 深色模式的层次与状态

- 画布使用中性炭灰 `#191919`，不使用纯黑或蓝紫渐变。冷色只轻微出现在外壳及侧栏，不能把整个页面染蓝。
- 从背景到前景依次为画布、设置分组、输入框/弹层；输入框必须明显亮于画布，不能仅把浅色背景替换为同一种深色。
- 设置分组为 `#232323`，输入框和弹层为 `#292929`，细分隔线为 `#373737`。通过面色区分层级，减少阴影；深色输入框无外投影，菜单可使用 `0 12px 32px rgba(0,0,0,.24)`。
- 主要文字为柔白，不把全部正文设为纯白；辅助说明为中灰，禁用态单独处理。不能把整组内容降低透明度而连带削弱提示和状态。
- 侧栏 hover 与选中分别为 `#282F37` / `#2D343C`；当前项通过持续背景及文字权重识别。主区 hover 保持中性灰，避免引入侧栏蓝调。
- 按钮分别定义默认、hover、pressed、focus-visible、disabled；禁用发送为灰色底和低强调图标，输入框仍可编辑；运行中的停止保持明确可见。
- 下拉菜单、代码块、滚动条、toast、审批、错误、图片预览遮罩都使用主题令牌。图片本身保持原色，代码语法色必须适配深背景。
- 切换主题只改变外观，不重连网关、不切换对话、不清空草稿；首次绘制读取主题，避免先亮后暗。跟随系统只在没有显式覆盖时响应系统变化。

## 6. 字体、图标与形状

字体：`"Segoe UI", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`；代码：`"Cascadia Code", Consolas, "SFMono-Regular", monospace`。使用系统字体，避免依赖在线字体加载。

| 类型 | 字号 / 行高 | 字重 |
|---|---|---|
| 空白页欢迎标题 | 28 / 38px；窄屏 24 / 34px | 400 |
| 设置页标题 | 24 / 32px | 500 |
| 对话标题 / 小节标题 | 16 / 24px | 500 |
| 消息正文 / 输入文字 | 15 / 25px | 400 |
| 导航 / 菜单 / 按钮 | 14 / 20px | 400；选中可用 500 |
| 元信息 / 状态 / 上下文 | 12 / 18px | 400 |
| 代码 / 命令日志 | 13 / 20px | 400 |

图标统一为线性风格，常规 16px，主要操作 18px，欢迎图标 40px；线宽约 1.5px。现有 SVG 可按此统一，不混用 emoji、Unicode 装饰符号和不同粗细的图标。图标按钮有可访问名称和提示。

圆角：普通按钮和列表项 8px；结果卡 10px；菜单 12px；弹窗 16px；输入框 20px；圆形发送按钮使用 50%。普通列表和正文无阴影；浅色输入框使用 `0 4px 20px rgba(20,30,45,.06)`，菜单和弹窗使用 `0 12px 36px rgba(20,30,45,.12)`；深色阴影按 5.1 节，通过表面差和边界保持层次。

## 7. 组件规范

### 7.1 侧栏与对话项

- 新对话采用普通线性图标和文字，行高 36px，无大面积彩色底。
- 搜索默认用紧凑入口，打开后显示输入栏；有查询条件时始终显示输入栏和清除入口。
- 对话名一行省略；hover、键盘聚焦及选中时可查看完整名称。
- 默认、悬停、选中三态明确区分。更多操作可在 hover 或 `focus-within` 出现；触摸环境始终提供入口。
- 运行中、待确认、待核对始终显示在对应对话右侧，不依赖 hover，不被更多菜单覆盖。
- 重命名、归档沿用现有能力；永久删除留在归档管理中并二次确认；归档成功可提供撤销。
- 工作区和设备名称来自真实配置；没有登录能力时不把本地用户 ID 描绘为已经认证的账号。

### 7.2 空白页

- 图标与欢迎语置于阅读区域中部略偏上，使用自然留白，不堆叠功能介绍卡。
- 有有效工作区时：`你想在 {工作区名} 中完成什么？`；无工作区时：`今天想完成什么？`。
- 工作区名过长时标题允许换行，不缩小全部标题字体。
- 可选显示截图中的单排四个起步入口：「探索代码 / 构建功能 / 审查改动 / 修复问题」。中性背景、细边框、16px 圆角，间距 12px，约 104px 高；只在新对话页显示，不在对话中堆叠。点击仅填入可编辑提示词，不能直接发送或承诺已有专用能力。窄窗口改为两列。图标默认中性，可使用少量低饱和类别色，但不承担全局强调色职责。
- 未完成首次配置时替换为 `先选择本机工作区` 和 `打开设置`，不能同时展示可发送状态。

### 7.3 输入区

- 输入框上方不显示项目、工作区、设备或分支上下文条，不保留其背景和占位高度；工作区和设备详情通过设置查看。运行时的任务摘要仍展示必要的执行来源。
- 输入框使用 elevated 表面（浅色白、深色中性灰），含文字区、附件区和底部工具栏。加号在左；模型、推理强度和速度保留现有菜单；发送在最右。
- 发送视觉尺寸 32px，点击区域至少 36px。普通图标按钮 32px；触摸目标至少 44px。
- Enter 发送，Shift+Enter 换行；中文输入法组合期间 Enter 不触发发送。
- 空草稿发送禁用；纯附件沿用当前可发送逻辑；发送中有明确文字或可访问状态。
- 运行中允许追加文字；发送与停止为独立操作，停止不因草稿为空而消失。运行中不支持的新附件选择应显示原因。
- 发送失败保留草稿并允许重试；结果未知显示 `核对发送结果`，不能直接引导重复发送。
- 菜单向上展开、自动避让边缘，不被草稿滚动区裁剪；Esc 关闭并把焦点交还触发按钮。

### 7.4 消息与结果

- 用户消息右对齐，使用浅灰背景和 16px 圆角，最大占内容轴的 85%；助手消息左对齐，无外层气泡边框。
- 消息组间距 24px，段落间距 12px。正文优先阅读，不常驻展示 Thread ID、请求 ID 或所有时间戳。
- 代码块使用中性浅灰表面，语言和复制操作置于同一工具栏；横向滚动仅限代码区域。
- 保留现有附件草稿、历史附件、查看大图、生成结果保存和失败重试。图片缩略图沿用最大 240×180px，图片卡最大 360px。
- 产物明确显示 `保存中 / 已保存到本机 / 保存失败 / 仅原设备可预览`，未经确认的中央路径不能显示为本机路径。
- 滚动阅读旧消息时不强制跳到底部；显示轻量 `回到最新`，主动点击后恢复跟随。

### 7.5 当前任务与执行日志

- 输入区上方保留紧凑任务摘要：阶段、耗时、目标设备与必要操作。
- 运行卡默认显示最新输出与展开入口；历史已完成卡折叠，长日志使用有界区域，不挤走输入框。
- 状态文字区分 `正在处理`、`等待本机执行`、`正在本机执行`、`本机操作结束，继续处理`；阶段必须来自真实事件，不能从等待时长推测。
- 完成、失败、超时、已停止、连接中断结果未知均有独立文案；显示退出码、截断及旧 Agent 不支持实时输出的说明。
- 命令完成不等于整个对话完成；停止只作用于当前对话，后台任务仍在对应侧栏项显示状态。

### 7.6 设置、表单与审批

- 设置为独立全页，复用 300px 浅灰蓝侧栏（窄桌面 272px）。顶部固定「返回应用」，下方为分类导航；主区和侧栏分别滚动。
- 主内容最大宽度 800px，左右安全边距 48px；内容顶部留白 64px，标题下方 40px 开始第一组。960px 以下边距收至 24px，短窗口顶部留白降至 32px。
- 分类只保留现有「常规与连接 / 对话管理 / 工作区与工具 / 诊断」。截图中的个人、集成、编码分组仅借鉴视觉层级，当前四类无需额外层级。
- 设置搜索作为后续可选能力；本轮不放置没有搜索行为的装饰输入框。
- 小节标题 14px / 20px、字重 500；标题到容器 16px；组间距 40px。
- 一组相关设置共用一个 group 表面容器（浅色白、深色 `#232323`）：1px 细边框、16px 圆角、无阴影。组内分隔线左右缩进 16px，最后一行没有分隔线。不为每个字段单独做卡片。
- 普通行最小高 64px，上下内边距 14px，左右 16px；说明文字可使行自然增高，不限制为固定高度。
- 行左侧为名称（14px / 20px、500）和说明（12px / 18px、次级色，间距 4px）；右侧为值、下拉框、按钮或开关，垂直居中，左右两区至少相距 24px。
- 短值右对齐，控件通常 120–220px 宽、32px 高。网关 URL、本机目录等长编辑字段另起一行占满可用宽度，高 36–40px；标签和帮助文字完整保留。
- 路径只读摘要中间省略，完整路径可聚焦查看或复制；「更改」按钮固定可见。显示值必须来自本机配置。
- 开关轨道 32×20px、滑块 16px，仅用于真实独立布尔选项；开启用 toggle-on 蓝色，关闭用中性色，滑块为白色。可访问名称包含设置项，状态通过语义暴露，点击区至少 36px。
- 当前统一配置继续使用显式「保存并应用」，不因为截图展示开关就改成自动保存。未保存、保存中、已应用、失败和忙碌不可应用状态分别呈现；失败不清空编辑内容。
- 操作栏与设置内容同宽，提供清晰的保存入口；有未保存改动时离开页面需要处理保存或放弃，不能静默丢弃。此交互属于确认后实施项。
- 内容区不足 560px 时，右侧控件移到说明下方并左对齐，长路径和错误换行；底部操作区不遮住最后一行。
- 普通错误贴近字段；连接错误放在连接区域；不以大块红色渐变横幅装饰页面。
- 审批单独展示动作、目标设备、工作目录和影响范围，保留接受与拒绝入口；不可被新消息或浮层遮挡。
- 主界面使用用户能理解的文案；协议字段、中央地址和原始事件留在诊断页。开发模式入口不得变成正式客户端默认路径。
- 用户截图中的「完整访问权限」及说明只用于外观参考，不能作为放开权限或自动批准的指令；不得新增无后端能力支撑的权限开关。

## 8. 状态矩阵

| 状态 | 显示位置和文字 | 操作及恢复 |
|---|---|---|
| 网关已连接，设备在线 | 侧栏底部两行：中央网关 · 已连接；本机设备 · 在线 | 可发送；详情进入设置 |
| 网关连接中 / 重连中 | 侧栏对应行 + 必要时输入区短提示 | 保留草稿；按真实连接策略恢复 |
| 网关离线 | `中央网关未连接` | 重连 / 打开设置；禁止提交 |
| 网关在线，设备离线 | `本机设备离线`，网关仍显示已连接 | 设备诊断；依据现有发送条件禁用相关操作 |
| 对话加载中 | 仅列表或消息区骨架，输入区保留布局 | 超时后显示重试，不能无限转圈 |
| 当前对话运行中 | 输入上方阶段摘要；侧栏该项 `进行中` | 追加文字 / 停止当前对话 |
| 后台对话运行中 | 对应侧栏行显示状态 | 切换查看；不劫持当前对话 |
| 等待审批 | 对应侧栏 `待确认` + 当前审批面板 | 明确接受 / 拒绝 |
| 提交结果未知 | 原消息状态 + 输入区 `待核对` | 核对历史；确认未提交后才允许重试 |
| 执行断线 | `连接中断，执行结果待核对` | 重连核对；不显示已成功 |
| 执行结束 | 卡片显示已完成 / 失败 / 超时 / 已停止 | 按真实结果显示后续动作 |
| 操作反馈 | 成功 toast 约 3 秒，普通提示约 5 秒 | 关键失败持续保留到处理或关闭 |

每个异步操作需要定义成功、失败、超时或取消等终态；UI 不擅自修改现有协议超时，不把耗时较长的模型或命令误报为失败。长等待显示耗时和可用操作，无法确认时明确标记未知。

## 9. 响应式、键盘和动效

- ≥1200px：300px 侧栏，760px 内容轴，主画布居中留白。
- 960–1199px：272px 侧栏，内容自适应，保持最小安全边距。
- 720–959px：默认折叠侧栏，通过标题栏按钮打开抽屉。
- <720px：侧栏抽屉、主区 16px 边距；输入工具栏可分行，发送与停止保持可见；作为小窗口兼容，不承诺移动端产品。
- 桌面建议验收 1152×772、1440×900、1920×1080；另检查 800×600、系统缩放 125% / 150% 和小宽度无溢出。
- Tab 能覆盖所有主要操作，菜单和弹窗有焦点管理；焦点环 2px、外扩 2px。选中、警告和错误不能只靠颜色区分。
- 颜色和透明度过渡 120–160ms，抽屉/弹窗 180ms；普通按钮不跳动。减少动态效果设置下取消非必要动画。
- 流式文本不逐 token 淡入，不重复朗读每个 token；阶段和完成状态通过适度的 live region 通知。
