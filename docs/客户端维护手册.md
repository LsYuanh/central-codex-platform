# 客户端维护手册

## 计划模式与目标模式（2026-09-24，开发版未发布）

2026-09-28 开发版将文件、目标和计划入口统一放入输入栏左下角「＋」。点击后向上展开等宽菜单；选择「计划模式」显示可关闭的「计划」标签，选择「目标」显示「目标」标签并聚焦主输入框。中央未声明能力时隐藏相应菜单项；模式按对话保存，下一次发送生效。

2026-09-24 中央已更新为 0.1.3 / revision 14，现有开发客户端重连后可用。使用时新建对话，在「＋」菜单选择「计划模式」再发送需求；计划生成后点击消息末尾的「开始实施」。目标模式在默认模式下点击「＋ → 目标」，直接在主输入框填写目标与可衡量的验收条件，按 Enter 或发送按钮启动。英文界面对应 Plan、Goal、Send。已发布安装包 0.2.9 不含这两个入口，本次未发布新版工作客户端。

- 计划模式：读取客户端文件、搜索、Git 状态/差异与同用户对话历史；中央和 Harness 双层拒绝写文件、通用命令和会投影资源的技能调用。模型可以提出结构化问题，用户可选答案、自由填写或跳过；计划作为正文展示，点击「开始实施」切回默认模式并发送实施请求。
- 目标模式：通过主输入框设置文字目标与验收条件，不提供 Token 预算设置，新目标不设预算。复用 Codex 原生目标及续跑机制，持续到完成、暂停、遇阻或额度受限；上方窄状态条显示原生状态、目标摘要和用时，编辑面板保留累计 tokens 与耗时。完成由模型根据执行结果确认。
- 暂停目标或停止任务会先暂停目标，再中断当前轮次，防止自动续跑；继续需明确点击「继续目标」。历史预算限制在用户显式继续或保存修改时清除，不自动恢复历史目标。清除目标保留对话历史。
- 设备离线或该设备最后一个工作客户端连接断开时，中央暂停目标；重新连接、重启 Worker 或恢复历史不会擅自恢复暂停目标。关窗驻留托盘且连接正常时，目标可继续；真正退出客户端会断连并暂停。

新对话点击「＋ → 目标」只切换输入方式，不创建空对话；发送时才创建对话并调用原生目标接口，不额外发送普通 turn。发送成功清空输入框、退出目标草稿模式，后续输入作为普通消息或运行中追加要求，不覆盖目标。点击「目标」标签退出草稿模式，保留文字与附件；模式与草稿随对话切换恢复。目标接口只接收文字，已有附件或技能标记会阻止目标提交并提示移除，保留草稿，可退出目标模式后正常发送。

已有目标显示输入框上方状态条，点击正文或展开按钮打开右侧「编辑目标」面板，窄窗口以覆盖式面板显示。直接修改全文，顶部提供「保存」与「撤销修改」，Ctrl/Cmd+Enter 也可保存；普通 Enter 在目标正文内换行。主聊天输入框及其草稿不变。关闭或 Esc 不提交、不暂停目标，未保存内容按对话保留；撤销回到最新已读取目标。编辑面板与加号/模型菜单互斥，但桌面点击聊天区不会收起编辑器；窄窗口限制键盘焦点在面板内，关闭后恢复触发位置。

保存前读取最新目标：运行中的目标先暂停并中断当前轮，将新正文以无预算且暂停状态保存，再恢复执行；原本暂停、遇阻、受限或已完成的目标修改后保持暂停，需显式继续。编辑期间只是修改草稿，原目标照常运行。提交失败保留正文与错误，若已暂停则不自动恢复；可刷新核对，再按需继续。远端目标被修改时提示撤销载入最新目标，被清除时禁用保存，避免按旧草稿覆盖已知的新状态。正文长度沿用 4000 字符限制。

状态条保留清除和暂停/继续操作。停止任务会取消尚未发出的保存续跑步骤，沿用中央先暂停再中断的逻辑。所有目标状态和编辑草稿按对话隔离。

发送失败保留正文与目标草稿模式；再次发送前先回读原生目标，同一目标已存在时只确认成功，不重复启动，也不覆盖其他已有目标。计划中不能启动目标，已提交计划需先开始实施。目标运行仍占用该用户并发额度，包括自动轮次之间的间隙；目标绑定创建对话的客户端设备。

实现入口：`App.tsx`、`GoalPanel.tsx`、`UserInputQuestions.tsx`、`conversation-content.ts` 及中央 `task-control.ts`。验证范围见[验证手册](验证与已知限制.md)。

## 简体中文 / English（0.2.9 已发布）

语言选择使用应用样式下拉菜单（已替换此前分段控件），选中项带勾选；支持鼠标、方向键、Home/End、Enter/空格确认，Esc/Tab/点击外部关闭。语言选项集中在 `LanguagePicker.tsx`，新增语言还须同步 i18n 资源及原生语言支持；不因增加选项重做控件布局。外观的主题、语言行使用相同上下内边距，分组间距保持 24px。

在「设置 → 常规与连接 → 外观」的主题下方选择「语言 / Language」。提供简体中文和 English，默认简体中文，立即生效。设置仅影响当前电脑，不同步到中央账号；语言包随客户端内置，离线也可切换，不改变模型回答语言、不重连中央或重启 Agent。聊天正文、代码、命令输出、文件/项目/技能名称、技能正文、中央发布说明和未知原始错误保留原文；快捷示例提问按点击时的界面语言填入。

侧栏、聊天操作、设置、配对、归档、技能管理、更新、附件/图片/Markdown 操作、无障碍标签使用统一词条。日期按所选语言显示，聊天数量支持英文单复数。应用自有错误/成功提示保存 key 与参数，到渲染时再翻译，包含恢复历史、后台通知和已知原生错误；原生错误匹配只位于 IPC 边界，不对用户/模型内容做全局替换。

桌面以应用配置目录内 `desktop-language-v1.txt` 为唯一持久化来源，临时文件原子替换；启动先读偏好，再渲染页面。浏览器开发预览使用独立 localStorage 键 `yuanzhou.desktop.language.v1`。读取失败/损坏回退中文；保存失败显示可重试错误并保持当前页面语言。读写等待最多 5 秒，避免卡住初始页面或选择器；超时后实际保存结果可能尚未确认，可重新选择核对。新增原生 `desktop_language` / `set_desktop_language` 仅管理 UI 偏好与菜单，不触碰连接凭据和业务配置。

托盘「新对话 / New chat」「退出远舟 / Quit YuanZhou」随语言同步，启动从已保存偏好生成。系统文件/目录选择框的应用标题随语言变化，操作系统自带按钮仍跟随系统语言；WebView 启动前故障框和安装器保持既有行为。核心入口：`src/i18n.ts`、`src/locales/en.ts`、`src/locales/native-en.ts`、`src/native-invoke.ts`、`src/LanguagePicker.tsx`、`src-tauri/src/language.rs` 与 `tray.rs`。使用中文源文案作类型受检的 key，新增 UI 文案必须同时维护英文词条；数字语法使用 count，异步提示使用 `message` / `UiError` / `useMessageState`，不要把已翻译结果长期存入状态。

Windows 隔离 Tauri 中英文、双主题与真实进程重启持久化已验证，具体证据与缺口见验证手册。未生成安装包、未升级已安装客户端、未发布或部署中央。

## 复制对话 ID 与引用历史（2026-09-22，开发版未发布）

普通列表的「更多操作 → 复制对话 ID」复制纯 ID；运行中、等待确认和繁忙时仍可复制，但重命名、归档等修改操作保留禁用。归档列表增加同名图标按钮。成功提示自动消失；失败/五秒超时显示可选中的 ID、重试与关闭入口。复用 `ThreadActions.tsx`，复制反馈由 `useThreadIdCopy.tsx` 管理。

配套中央升级后，在新对话输入「查看对话 `<ID>`，总结之前的结论」即可由模型调用 `conversation_read`。只允许同一用户，包括其其他设备上的历史和归档对话；复制 ID 不授予跨用户访问权，也不改变对话的执行设备。读取不会启动、恢复或修改目标对话，不需要目标设备在线。

默认返回用户消息与助手回复，区分进度/最终回复；需要时读取已保存的工具文字结果。长历史有续读位置，未读完不能宣称已读全文；历史变化会要求重新开始。运行中的历史明确标记进行中；附件只返回名称或不可读取提示，不打开原始文件。旧对话可作为读取目标，但其工具快照不迁移：发起读取需升级后的新对话。处理过程显示「读取对话历史 · 中央只读」。源码实现不代表正式中央已支持；验收缺口见验证手册。

## Local Agent 生命周期

桌面在配置就绪后启动自己的 Local Agent。0.2.6 起点击主窗口关闭按钮（含 Alt+F4）会隐藏到系统托盘，保留窗口、连接、对话草稿和 Agent，正在进行的任务继续运行。单击托盘图标恢复并聚焦窗口；右键仅提供「新对话」「退出远舟」。真正退出（托盘退出、macOS 应用菜单/Cmd+Q）时才停止并回收 Agent，安装更新期间禁止手工退出。无需用户手工启动 Agent，也无需安装本地 Codex、CLI 或 App Server。

客户端按应用标识单实例运行：窗口可见、最小化或驻留托盘时再次启动，都恢复现有窗口，不新增客户端/Agent。不同隔离测试标识互不影响。「新对话」复用侧栏入口，保留已有草稿和设置未保存提示；尚未连接时打开连接设置，初始化/发送/切换对话/更新安装期间暂不可用，有模态对话框时先保留该对话框。入口 `src-tauri/src/tray.rs`、`src/use-tray-new-conversation.ts`、`src/App.tsx`；单实例插件先于其他插件及 Agent 初始化。

开发入口 `npm run dev:desktop` 先构建 Agent。开发可执行文件默认与 Agent 相邻；安装包使用 Tauri `externalBin`，Windows 位于程序同目录，Mac 位于 `.app/Contents/MacOS/`。Tauri 与 Agent 使用继承匿名管道处理本机 IPC，Agent 主动出站连接中央 `/ws/agent`。

保存配置前由 Agent 检查活动命令和传输。忙碌、提交状态未知时禁止切换；无效配置保留旧进程，启动或原子保存失败时恢复旧配置和 Agent。网关连接、Agent 进程已启动、设备已在线是不同状态，不能互相替代。

## 文件与执行边界

中央只推理和路由；文件、Git、PowerShell 和其他命令由目标客户端 Agent 执行，受本机系统账号权限约束。

| Agent 能力 | 路径和历史行为 |
| --- | --- |
| `client-paths/v1` | 绝对路径及相对路径可访问配置目录外；相对路径从默认输出目录解析，允许父目录；支持普通 UNC 与显式目录链接，拒绝盘符相对路径和设备命名空间 |
| 仅既有 `remote-workspace/v1` 与设备身份能力 | 保持原工作目录边界和输出位置，无需为工作目录内功能强制升级 |

新版未指定 `path`、仅给 `name` 的文件和图片保存到 `file/output_paths.outputDirectory`。既有输出不迁移；`downloads` 只报告真实下载目录。项目规则按目标目录祖先链读取，Git 可操作其他项目和普通 worktree；递归搜索跳过链接且保留分页、大小和超时限制。

Thread 始终绑定用户与设备安装身份。新版更改默认输出目录不使原 Thread 失效，但每次请求和审批期间仍核对目录配置。补丁预览返回 `expectedPaths` 与 `expectedVersions`，批准后再次核对真实路径与文件 SHA-256；链接重定向、版本冲突、部分成功和未知结果不得自动重放。旧 Agent 使用其原有预览协议，新版缺少目标校验字段不能降级。

命令按行或每 250 ms 回传输出；默认超时 30 分钟，可在 1 秒至 2 小时内调整。最终结果每流最多 64 KiB，实时展示每流最多 1 MiB；截断后继续排空管道。中断调用 `job.cancel` 结束关联进程树，断线取消在途命令。Windows Agent 使用 kill-on-close Job，启动 Job 失败明确报错。

命令输出优先 UTF-8，识别 UTF-8/UTF-16 BOM；Windows 非法 UTF-8 回退到本机 OEM 代码页，截断保留完整字符。混合编码、任意自定义代码页及无 BOM 的 UTF-16 不保证自动识别。

## 对话、附件和结果

2026-09-22 开发版补齐结构化结果：

- 附件和输出卡片显示扩展名/类型、大小及原有读取/保存状态，文件位置可展开，支持复制路径和打开所在目录。定位前经 Local Agent 核对来源设备、已有安装身份及版本；未保存、已变化或不可用的文件明确报错。PDF/Office 仍为文件引用，本轮没有增加内嵌文档解析或预览。
- 正文、附件和输出图片共用 `ImageViewer.tsx`，支持放大、缩小、原始尺寸、适应窗口、滚动查看及 Esc 关闭；Tab 焦点保留在预览内，关闭返回触发按钮。本机大图经 `file-preview.ts` 调用原 Agent 读取接口，最多 20 MiB、256 KiB 分块，校验位置/长度/结束标记并关闭传输；文件或来源变化会取消旧预览。HTTPS 图片直接加载原地址，不发送 referrer；加载失败/15 秒超时有提示。没有新增后台下载或文件写入。
- 命令日志可筛选全部/标准输出/错误输出/进度并复制当前分类，保留各状态、退出码和截断提示；用户向上翻阅时新增日志不强制跳到底部。
- 经协议校验的本机 Git diff 与显式 `diff`/`patch` 围栏使用 `DiffView.tsx`，按 `diff --git` 文件分组，标出增删和前后行号，支持折叠、源码切换和复制。二进制等元信息保留原文。超过 200,000 字符或 3,000 行回退源码；截断统计仅反映收到的内容。仅展示已有结果，不自动执行修改。
- 显式 `json` 围栏使用 `JsonView.tsx`，完整合法内容可切换树形和带高亮源码，复制始终保留原始文本。每层先显示 100 项，可继续展开；深度达到 32 时提示查看源码。生成中、无效、超过 100,000 字符或含不安全整数/非有限数值时回退原文。普通正文不自动识别为结构化结果，不生成操作按钮。

2026-09-22 开发版使用统一的 Markdown 阅读组件，适用于新回复、历史消息和技能文件预览。支持标题、强调组合、删除线、引用、多级列表、只读任务清单、分隔线、表格与列对齐、引用式链接和脚注。脚注 ID 按消息隔离，可跳转并返回正文；表格、长代码及图表在内容区域内滚动，不撑宽整个对话。保留聊天中的普通换行。

代码块支持常用语言及 PowerShell 高亮、复制成功/失败提示，未知语言保留原文。使用 `$...$` / `$$...$$` 表示行内/独立数学公式，使用 `mermaid` 代码围栏表示流程图、时序图、状态图等。公式、高亮和图表按需加载；流式生成时公式、图表先展示源码，消息完成后绘制，语法错误保留源码并提示。图表严格模式，不接受 frontmatter/初始化配置指令；图表最多 30,000 字符、500 条边，公式最多 20,000 字符，超限回退源码。图表有 15 秒等待终态及源码查看入口。

Markdown 图片支持 HTTPS 地址（不发送 referrer）与当前对话已登记的图片附件/输出文件。绝对路径或本机 file URL 仅用于匹配既有文件元数据；优先使用该消息的记录，不把中央文件路径当成本机路径，也不因正文出现路径就直接读取任意文件。本机图片沿用 Local Agent `attachment/identity`、`attachment/preview` / `attachment/output_preview`，校验设备、输出安装身份和原文件版本；未登记、已变化、设备不符或加载失败有提示及重试，图片加载超时为 15 秒。技能预览没有对话附件上下文，因此本机图片引用显示未关联提示。现有附件/输出卡片及大图入口保留。

网页和邮件链接通过系统应用打开；脚注在当前页面跳转。2026-09-22 根据真实对话补充经过过滤的 HTML 子集：`details/summary` 折叠块、`kbd` 按键、`sub/sup` 上下标、`mark` 高亮、`br` 换行，以及普通文本结构。`p/span` 仅接受单条 `color` 声明：red/orange/yellow/green/blue/purple/pink/gray/grey/black/white 或十六进制颜色；命名色适配主题，十六进制保留指定值。不接受任意 CSS、脚本、事件、表单、iframe 或内嵌 SVG。`markdown-html.ts` 先过滤再为每条消息的 ID/锚点添加独立前缀；HTML 图片继续走既有预览校验。代码围栏内的 HTML 仍显示原文，不执行。中文斜体允许字体合成；图片失败重试为 28px 紧凑按钮，粗指针保持 44px。

客户端 CSP 仅为正文图片新增 HTTPS 图片源，链接权限增加 mailto；中央网关、Agent 协议和文件执行边界不变。这些展示能力尚未打包发布，验证范围见验证手册。

单窗口可并行多个 Thread，每个 Thread 一个活动 Turn；草稿、审批、日志、提交状态独立。运行中可追加文字，停止只影响当前对话。同轮追加不重置用时，完成、失败和停止后保留耗时。执行过程在运行时默认展开，第一段非空最终回答（`final_answer`）或最终回答附件出现时自动折叠；进度消息和空回答占位不触发折叠，无最终回答的任务结束时也回到默认折叠。保留手动展开/收起，同阶段的时钟更新与流式片段不会覆盖手动选择；最终回答期间手动展开后正常完成也保留展开。历史已完成任务默认折叠，可通过用时入口查看；最终回复和必要提示保持可见。此折叠行为于 2026-09-21 更新源码，随 0.2.6 发布。

2026-09-24 开发版输入框右侧发送与停止互斥显示：运行时在发送位置显示单个无边框停止按钮，使用发送的粉色底与白色图标；结束后恢复发送。运行中仍可输入文字并按 Enter 追加要求，按钮点击只停止当前任务；停止语义和协议不变。此修改尚未打包发布。

附件从加号、拖拽或截图粘贴添加；准备阶段仅本机 IPC，发送后才向中央提交推理所需内容。失败保留草稿；未知提交先核对历史，不自动重复发送。图片单张 5 MiB、每轮总计 10 MiB、最多 10 个附件，尺寸不超过 8192×8192 且不超过 1600 万像素。传输使用 256 KiB 分块。PDF/Office 当前仅作文件引用，没有内置解析器或宏执行。

## 排障

2026-09-24 开发版修复页面刷新/HMR 后遗留原生连接：旧版最多累计四条后，新连接被拒绝，但通用文案显示成“中央连接或 TLS 证书校验失败”。新版本在原生页面加载时清理旧连接、取消旧握手，前端卸载时关闭连接并停止该页面重连；关闭窗口驻留托盘不会触发页面清理。连接上限、页面已刷新和配对配置不符有单独错误码，未知错误不再推断为 TLS 问题。旧版遇此情况可从托盘完整退出远舟后重新打开，不能仅关闭窗口。排查时先用既有 CA 核对中央健康状态，再检查客户端连接数，不通过跳过 TLS 或重新配对处理连接残留。本修复已在当前 Windows 开发进程验证，尚未发布安装包。

### 客户端小包更新（0.2.5 起已发布）

后续 Windows 客户端小包不携带 WebView2，保留并复用已安装组件，包括 0.2.4 的独立运行时；正常使用系统 WebView2 的电脑继续沿用系统运行时。应用内更新和手动升级都会保留组件。小包不负责补装、修复或移除；需要这些操作时先安装客户端，再运行单独的远舟 WebView2 组件安装包，默认勾选为补装/修复，取消勾选为移除。组件包使用对应正式/RC 客户端注册目录，操作前需关闭客户端，不更改配对、设置和历史。

已选组件缺关键文件时，小包会中止并提示先修复，避免覆盖旧程序后才发现无法启动；原生启动错误框也指向独立组件包。固定运行时仍需按安全/兼容性需求单独升级。已发布 0.2.4 安装包保持原有完整包行为；当前 0.2.6 更新清单使用小包，0.2.5 完整包保留为修复基线。

### Windows 可选独立 WebView2（0.2.4 已发布）

面向 Windows 10/11 x64，完整安装包增加“安装独立 WebView2 运行环境”复选框。首次默认不勾选，使用系统 WebView2；勾选后使用安装目录 `WebView2Fixed` 中的专用运行时，不替换系统 WebView2。组件包含在完整包中，用户安装时无需下载；不勾选仍会下载完整安装包，但不安装组件文件。macOS 继续使用 WKWebView，中央服务和 Agent 协议不变。

已有用户可以重新运行安装器，选择添加/重装并勾选组件；组件操作不修改配对、设置和历史。升级读取上次选择，应用内被动更新不弹出选项、不强制添加；交互安装取消勾选会移除组件并恢复系统运行时。正常卸载移除专用运行时，更新模式保留它。不要将“独立运行时”当作所有白屏问题的通用修复，显卡、安全软件或用户数据权限问题仍可能需要排查。

客户端在窗口创建前选择运行时。已选组件缺文件、清单无效或窗口构建失败时，显示不依赖 WebView 的原生错误框；日志位于 `%LOCALAPPDATA%\com.centralcodex.localspike\startup.log`，RC 使用其独立 identifier 目录。日志记录运行时选择、版本和启动错误，不记录配对秘密或消息。选中组件损坏时不静默切回系统；应重跑支持该组件的安装器进行修复。

安装器拒绝独立运行时位于 UNC、目录链接或含链接的组件树；更新先暂存新运行时，设置 Windows 10 AppContainer 所需读取/执行权限，再切换目录。组件目录切换失败时尝试恢复旧目录；这不等于整个应用安装具备自动回滚。安装包及故障电脑的真实验收范围见[验证手册](验证与已知限制.md)。

| 现象 | 检查和恢复 |
| --- | --- |
| 网关在线、设备离线 | 检查本机 Agent 是否随桌面启动、配对授权及 `/ws/agent`；不要把中央目录当成本机结果 |
| 证书或网络错误 | 按固定错误码检查系统时间、证书有效期、主机名、信任链或连接超时；配对、HTTP 和 WSS 已统一 Rustls，保留 TLS 验证 |
| 授权撤销或用户停用 | 显示终态并停止重连；管理员恢复可用身份后重新配对 |
| 提交或执行结果未知 | 先核对历史与实际文件；不以新消息 ID 自动重试修改 |
| `MODEL_CREDENTIAL_EXPIRED` | 转中央端按[模型认证手册](模型认证维护手册.md)处理；原失败任务须用户手动重发 |
| 缺少 `VCRUNTIME140.dll` | 0.2.2 的 Agent 已静态链接 CRT；使用完整 0.2.2 安装包覆盖，故障电脑仍需实测 |

## 个人技能（中央已升级，客户端 0.2.6 已发布）

侧栏和设置提供「我的技能」，输入框通过 `$` 唤起技能候选列表。个人技能按平台用户保存，同一用户可在不同客户端调用；草稿仅在创建它的设备可见。正式中央网关与 Harness 已升级，客户端 0.2.6 安装包与更新清单已上线。升级后重新连接并新建对话，以获得新增的动态技能工具，旧对话保留原工具快照。中央初始化必须带 `yuan-zhou-managed-skills/1`，Local Agent 必须声明 `skills/v1`。

2026-09-22 开发版页面按技能目录重新布局：仅保留一组标题，顶部提供名称/说明搜索、刷新和创建入口；宽屏双列、窄屏单列，点击条目进入详情。详情顶部提供启用开关，「更多技能操作」内管理自动匹配和对话修改，底部删除需二次确认。Markdown 默认阅读视图隐藏 SKILL.md 头部元数据，可切换源码或其他资源文件；文件切换失败保留原文件与内容，预览不执行脚本。 文件选择使用应用内主题菜单，显示文件图标、大小和选中勾号；鼠标点击不显示蓝色焦点框，键盘焦点使用中性色描边。支持方向键、Home/End、名称前缀定位、Enter/空格选择，Esc 仅关闭菜单，Tab 或点击外部收起；长列表在弹窗内滚动。

详情的「立即使用」进入独立的新对话草稿，预选技能并携带 ID/版本，光标置于标记之后；输入需求后发送，不自动提交任务。该草稿不继承原对话附件，也不覆盖普通新对话的未发送草稿；技能停用或设备/连接不可用时禁用此入口。发送仍使用现有版本和依赖校验。

1. 点击「创建技能」，在新对话补充用途、输入输出和触发条件。AI 按创建提示在客户端草稿目录生成文件。
2. 返回「我的技能」→「本机草稿」→「预览并保存」，逐个检查说明、模板、参考资料和脚本，再确认保存。预览只读取文件，不运行脚本；保存的是该次预览的完整快照，预览之后发生的文件修改不会混入。预览有效期十分钟。
3. 在输入框输入 `$`，上方弹出技能列表，继续输入可按名称或说明筛选；`↑↓` 切换、Enter 选择、Esc 关闭，列表打开时 Enter 不发送消息。选中后显示粉色图标与名称的行内标记，继续输入正文后发送；2026-09-22 已移除输入框底部的「技能」按钮，统一使用 `$` 触发候选。支持多个技能，显式一次最多四个；标记整体删除，草稿保留技能 ID 与所选版本，发送时发现更新/停用/移除会提示重新选择。运行中追加仍只支持普通文字，新技能在下一轮调用。也支持模型按描述匹配，可单独关闭「自动匹配」或停用技能。
4. 「对话修改」复制当前版本到新的本机草稿。保存前若其他客户端已更新或切换状态，拒绝旧版本覆盖，需新建修改草稿。删除/停用阻止后续加载，已执行中的脚本不会被自动终止。

2026-09-21 `$` 选择交互已随 0.2.6 发布。入口 `SkillComposer.tsx`；普通文本和复制内容使用 `$name` 表示，粘贴仅接收纯文本，图片继续走已有附件流程。编辑器保留中文组合输入、Shift+Enter 换行、撤销重做及草稿切换；切换对话隔离撤销历史。

技能包需要 UTF-8 `SKILL.md`，YAML 头部中 `name` 为小写字母开头的英文、数字、连字符（最多 64 字符），`description` 使用单行字符串（建议双引号，最多 1024 字符）。允许 `references/`、`assets/`、`scripts/` 等相对路径资源和二进制模板；禁止链接、路径逃逸、Windows 保留名和大小写重名。最多 64 文件/8 MiB，SKILL.md 最大 64 KiB；每个用户最多 100 个技能、总计 32 MiB、30 个草稿。正文每文件预览最多 64 KiB，保存仍包含完整文件。

可选 `runtime.json` 示例：`{"platforms":["windows"],"programs":["python"]}`。平台支持 windows/macos/linux，空数组不限制；programs 仅检查客户端 PATH 下是否存在命令，不自动安装、不验证版本或语言模块。技能不能开启插件、MCP、子代理、原生图片生成等禁用能力，也不能改变既有执行权限。脚本通过已有设备命令工具和相应解释器执行。

遇到中央/Agent 版本不匹配、离线、依赖缺失、系统不支持、传输校验失败，会显示可理解的失败信息，不继续提交显式技能调用。超时后先刷新核对结果。当前版本保留本机草稿及已下载副本，不自动递归删除用户可能修改的文件；「移除登记」只移除草稿登记。缓存位置为系统本地数据目录下的 `com.centralcodex.localspike/skills-v1/<用户哈希>/`，后续需按实际使用量规划缓存清理。

实现入口：`apps/desktop/src/skills.tsx`、`services/central-gateway/src/skills.ts`、`crates/local-agent/src/skills.rs`。验证范围见[验证与已知限制](验证与已知限制.md)。

## 远舟内置创建技能（2026-09-22，中央已部署，客户端 0.2.6 已发布）

技能目录、详情标题、`$` 候选和选中标记统一显示 `yuan-zhou-skill-creator`，来源仍为「远舟内置」，与中央 Codex 的 `skill-creator` 分离。候选可通过名称或中文说明搜索；复制和传输使用 `$yuan-zhou-skill-creator`，保留 ID/修订信息。客户端兼容旧中央和旧草稿中的中文 displayName；普通个人技能继续使用自己的显示名。页面操作按钮仍为「创建技能」。详情只读，不提供删除、停用或对话修改内置内容；更多菜单可以关闭自动匹配，显式使用不受影响。

新版中央提供内置条目时，页面「创建技能」「对话修改」统一进入预选内置技能的新对话，修改请求携带目标个人技能 ID，不提前创建空草稿，也不自动发送。连接尚无该条目的旧中央时保留原有创建草稿入口。对话中明确要求创建技能也可由模型自然匹配；是否匹配是模型行为，显式选择更确定。

创建流程为理解当前对话、逐个追问缺少的信息、确认方案、申请本机草稿、生成完整包、打开本机草稿预览并保存。脚本不会因生成而自动执行。`SKILL_CREATOR_NEW_THREAD_REQUIRED` 会显示新对话恢复入口；当前输入与附件保留，已发送的历史仍留在原对话，用户需要时可将相关上下文补入新对话。原个人技能若与保留名称同名，会保留文件但禁止调用，并提示通过对话修改名称。

入口：`skills.tsx`、`SkillComposer.tsx`、`App.tsx`。中央已按用户授权升级至 revision 11，客户端升级 0.2.6 后重新连接并新建对话即可使用；安装包和更新清单已发布。名称统一修订随本版生效，网关源码同步默认显示名，本次没有再次部署中央。开发窗口检查复用原单实例进程，真实模型及 Windows Agent 验收见验证手册。
