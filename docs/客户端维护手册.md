视觉重构进展（2026-09-20）：规范与首轮双主题实现后，用户要求按新提供的第二张 Codex 页面调整，已修订[UI 规范 V0.3 的当前优先规则](客户端UI设计规范.md)。侧栏改为自适应 248–304px 蓝灰外壳，主区恢复圆角与页头边线；正文和输入框统一 736px 内容轴，使用粉色用户气泡和发送强调色。过程入口恢复细分隔线，完成用时简写；正常连接恢复不再插入带 Thread 编号的聊天消息，编号仍在诊断页。五类设置继续共享令牌与布局，文件卡片、更多菜单和未保存提示保留。验证范围见[验证手册](验证与已知限制.md)。上述调整已随 0.2.3 发布。

按最新截图要求，长用户消息和助手正文仍始终完整显示，不再截断、渐隐或提供「展开完整内容/收起长内容」。向上滚动时显示圆形下箭头，居中悬浮于输入框上方，不单独占行；点击或手动回到底部恢复跟随并隐藏按钮。输入框覆盖消息滚动层，正文可滚入输入框后方，上方不预留空白栏；ResizeObserver 根据输入框高度同步消息末尾间距与箭头位置，确保最后一条回复可见。审批出现时恢复顺序布局，保持确认操作可达。执行过程、步骤、诊断输出的现有详情折叠保持独立。

## 本机项目（中央已部署，客户端 0.2.3 已发布）

侧栏「项目」的加号创建项目，使用系统目录选择器关联本机已有文件夹。每项目支持 1–8 个目录，第一个为主目录；名称最长 80 字符，每用户每设备最多 100 个项目。项目元数据保存在中央网关状态中，按用户与设备隔离；文件夹存在性和规范路径由该设备的 Local Agent 验证，中央不访问这些目录。

项目行通过开/闭文件夹图标表示展开状态；对话不带前置图标，使用紧凑文字行。默认显示排序后的前五个对话，支持展开更多、项目置顶及折叠。侧栏顶部直接显示新对话，移除重复产品名和搜索框；项目与最近组间额外留白为 12px，添加本机项目的悬停颜色沿用侧栏。鼠标悬停或键盘打开更多按钮显示项目详情，提供目录、对话数量和编辑入口；Esc 关闭并返回焦点。

编辑窗口可改名、添加/移除源文件夹、设为主目录。保存采用修订号检查，多窗口冲突需刷新后重新编辑；超时或未知结果先核对列表，创建请求有幂等标识。移除本地项目只删除分组，对话回到「最近」，不删除本机文件、对话或原工作目录。列表读取、保存和删除均有错误提示及重试路径；旧中央服务显示需更新后启用项目。

项目内新对话捕获当时的名称和目录快照，默认在主目录执行命令并读取适用的项目规则；关联目录通过绝对路径使用，不自动共享其他对话历史。后续改主目录只影响新对话，已有对话继续使用原目录；目录失效会明确报错，不回退到默认输出目录。各项目未发送草稿在当前窗口内独立保留；置顶和展开偏好按连接/用户/设备保存在本机。退出应用不保证保留未发送草稿。

项目依赖新版中央网关的 `platformCapabilities.projects` 和 Agent 的 `client-paths/v1`。非项目对话及旧 Agent 原工作区行为保持兼容。文件工具的显式相对路径和补丁相对路径按主目录解释；只提供输出名称的文档/图片仍保存到配置的默认输出目录。尚不包含 Git 分支、worktree 隔离或任务转移。

入口：`apps/desktop/src/projects.ts`、`ProjectSidebar.tsx`、`App.tsx`；中央目录管理与路径转换在 `services/test-gateway/src/projects.ts`。协议见 [AgentRPC](../spikes/local-dev/AGENTRPC.md)，验证范围见[验证手册](验证与已知限制.md)。

### 对话排序与归类（2026-09-21，0.2.3 已发布）

选中项目内对话时，仅对话行保留选中背景；项目行仅鼠标悬停时显示背景，移开即恢复，键盘焦点仍有描边提示。

拖动对话文字行可调整同组顺序，也可拖入其他项目或「最近」。插入线表示落点，拖到分组标题放在该组顶部；悬停收起的项目约 600ms 后展开。Esc、窗口失焦或在目标之外松开取消拖拽。更多菜单提供「上移」「下移」「移动到项目或最近」，供键盘和触屏使用。

发送被接受或收到新的回复时，对话移到所属组顶部；同一 Turn 的流式片段仅触发一次，随后手动排序不会被后续片段覆盖。运行中成功追加消息会再次置顶；打开历史、选中对话和刷新列表不重排。

排序及归类覆盖存储在客户端 `yuanzhou-thread-layout-v1` 偏好中，按中央连接、用户和设备隔离，同源窗口通过 storage 事件同步；不跨客户端配置同步到中央。保存失败显示错误并保留原位置，可恢复本机存储后重试操作。归类不修改 Thread 的原项目目录快照和历史，也不执行 Git/worktree 或运行任务转移；移除目标项目后对话回到「最近」。实现入口为 `SidebarOrganization.tsx`、`sidebar-order.ts`。

### 新对话项目选择（2026-09-21，0.2.3 已发布）

客户端初始窗口为 1200×760；输入框本体默认约 100px，不含项目栏，多行文字和附件可撑高，清空后恢复默认高度。

新对话输入框上方显示项目栏；未选择时为「选择项目」，使用客户端默认工作目录。点击后可按项目名或目录搜索，列表显示名称、主文件夹名和选中标记，支持方向键、Enter、Esc 与焦点返回；底部提供「新建项目」「不在项目中工作」。新建复用现有目录选择与项目编辑窗口，创建成功自动选中；项目标签悬停或键盘聚焦时可取消选择。没有本地执行模式和 Git 分支入口。

选择器只改变当前草稿的目标，保留文字、附件和原草稿槽位，不覆盖目标项目在侧栏保存的另一份草稿。从侧栏项目新建时仍恢复该项目的草稿并自动选中该项目。首次发送按当前项目修订号捕获目录快照；之后隐藏选择器，已有对话只在页头查看原目录。所选项目已移除或不可用时，发送明确失败并保留草稿，不静默回退默认目录；用户可重新选择或取消项目。

实现入口为 `ComposerProjectPicker.tsx`、`App.tsx`，复用 `ProjectSidebar.tsx` 导出的 `ProjectDialog`。项目列表加载、错误与重试沿用现有服务，不改中央协议。未发送草稿仍仅保存在当前窗口内。

## 配对与配置

1. 中央管理员在“用户与设备”选择用户，生成并复制一体配对码。
2. 客户端连接设置粘贴完整的 `yzpair1.` 代码，点击“配对并连接”。代码包含中央 WSS 地址、公共 CA、一次性令牌及有效期；有效期五分钟，只可消费一次。
3. 确认默认输出目录并保存。当前正式地址为 `wss://192.0.2.10:4510/ws`，仅用于现有局域网。

新版不要求普通用户填写平台密码、用户 ID、设备 ID 或单独导入 CA。身份由服务端分配；旧版或高级设置仍可手工配置地址与公共 CA。重新配对不会转移旧 Thread 的设备绑定。取消本机配对后，如中央撤销未确认，仍须管理员核对撤销结果。

首次默认目录为系统 Documents 下的 `YuanZhou Workspace`，仅保存首次配置时创建。已有配置、配对及目录选择在升级时保留；用户指定的其他目录须已存在。Windows 配置位于 `%APPDATA%/com.centralcodex.localspike/desktop-runtime-v1.json`，macOS 由 Tauri 配置目录 API 定位。

开发覆盖变量：`CODEXIA_LOCAL_AGENT_PATH`、`CODEXIA_WORKSPACE_ROOT`、`CODEXIA_GATEWAY_AGENT_URL`。页面显示覆盖来源；移除覆盖并重启后恢复保存配置。保留内部 `workspaceRoot` 字段兼容旧配置，其产品含义已改为默认输出目录。

常规与连接页面离开时，若中央地址、身份或默认输出目录有未保存修改，会提示「保存并应用 / 放弃修改 / 继续编辑」。Esc 保留草稿；放弃恢复已保存配置；保存时沿用原有忙碌检查、校验、Agent 启动与重连流程，失败保留提示。主题是立即生效选项，不属于待保存配置。此提示针对应用内切页，不拦截原生窗口关闭。

## Local Agent 生命周期

桌面在配置就绪后启动自己的 Local Agent；关闭唯一窗口或 macOS 菜单退出时停止并回收 Agent。无需用户手工启动 Agent，也无需安装本地 Codex、CLI 或 App Server。

开发入口 `npm run dev:desktop` 先构建 Agent。开发可执行文件默认与 Agent 相邻；安装包使用 Tauri `externalBin`，Windows 位于程序同目录，Mac 位于 `.app/Contents/MacOS/`。Tauri 与 Agent 使用继承匿名管道处理本机 IPC，Agent 主动出站连接中央 `/ws/agent`。

保存配置前由 Agent 检查活动命令和传输。忙碌、提交状态未知时禁止切换；无效配置保留旧进程，启动或原子保存失败时恢复旧配置和 Agent。网关连接、Agent 进程已启动、设备已在线是不同状态，不能互相替代。

## 文件与执行边界

中央只推理和路由；文件、Git、PowerShell 和其他命令由目标客户端 Agent 执行，受本机系统账号权限约束。

| Agent 能力 | 路径和历史行为 |
| --- | --- |
| `client-paths/v1` | 绝对路径及相对路径可访问配置目录外；相对路径从默认输出目录解析，允许父目录；支持普通 UNC 与显式目录链接，拒绝盘符相对路径和设备命名空间 |
| 仅既有 `remote-workspace/v1` 与设备身份能力 | 保持原工作目录边界和输出位置，无需为工作目录内功能强制升级 |

新版未指定 `path`、仅给 `name` 的文件和图片保存到 `file/output_paths.outputDirectory`。既有输出不迁移；`downloads` 只报告真实下载目录。项目规则按目标目录祖先链读取，Git 可操作其他项目和普通 worktree；递归搜索跳过链接且保留分页、大小和超时限制。

Thread 始终绑定用户与设备安装身份。新版更改默认输出目录不使原 Thread 失效，但每次请求和审批期间仍核对目录配置。补丁预览返回 `expectedPaths` 与 `expectedVersions`，批准后再次核对真实路径与文件 SHA-256；链接重定向、版本冲突、部分成功和未知结果不得自动重放。旧 Agent 使用其原有预览协议，新版缺少目标校验字段不能降级。

命令按行或每 250 ms 回传输出；默认超时 30 分钟，可在 1 秒至 2 小时内调整。最终结果每流最多 64 KiB，实时展示每流最多 1 MiB；截断后继续排空管道。中断调用 `job.cancel` 结束关联进程树，断线取消在途命令。Windows Agent 使用 kill-on-close Job，启动 Job 失败明确报错。

命令输出优先 UTF-8，识别 UTF-8/UTF-16 BOM；Windows 非法 UTF-8 回退到本机 OEM 代码页，截断保留完整字符。混合编码、任意自定义代码页及无 BOM 的 UTF-16 不保证自动识别。

## 对话、附件和结果

单窗口可并行多个 Thread，每个 Thread 一个活动 Turn；草稿、审批、日志、提交状态独立。运行中可追加文字，停止只影响当前对话。同轮追加不重置用时，完成、失败和停止后保留耗时。执行过程默认折叠，运行时显示状态摘要，完成后通过用时入口展开；最终回复和必要提示保持可见。

附件从加号、拖拽或截图粘贴添加；准备阶段仅本机 IPC，发送后才向中央提交推理所需内容。失败保留草稿；未知提交先核对历史，不自动重复发送。图片单张 5 MiB、每轮总计 10 MiB、最多 10 个附件，尺寸不超过 8192×8192 且不超过 1600 万像素。传输使用 256 KiB 分块。PDF/Office 当前仅作文件引用，没有内置解析器或宏执行。

剪贴板临时图片由 Agent 登记，容量上限 100 MiB，保留七天并在后续导入时清理过期登记项；移除附件不删除用户源文件。预览和输出依赖原设备及原文件版本；中央 `savedPath` 不能当成本机文件。平台保存元数据，App Server 自身仍可能保留内容。

当前固定 Harness 禁用未适配的原生图片生成、插件和子代理；旧图片/附件历史、已有输出保存和本机文件工具继续保留。不能把早期图片生成验收当作当前已开放该能力。

## 排障

### 客户端小包更新（源码已实现，尚未发布）

后续 Windows 客户端小包不携带 WebView2，保留并复用已安装组件，包括 0.2.4 的独立运行时；正常使用系统 WebView2 的电脑继续沿用系统运行时。应用内更新和手动升级都会保留组件。小包不负责补装、修复或移除；需要这些操作时先安装客户端，再运行单独的远舟 WebView2 组件安装包，默认勾选为补装/修复，取消勾选为移除。组件包使用对应正式/RC 客户端注册目录，操作前需关闭客户端，不更改配对、设置和历史。

已选组件缺关键文件时，小包会中止并提示先修复，避免覆盖旧程序后才发现无法启动；原生启动错误框也指向独立组件包。固定运行时仍需按安全/兼容性需求单独升级。已发布 0.2.4 安装包保持原有完整包行为；新小包尚未打包发布。

### Windows 可选独立 WebView2（0.2.4 已发布）

面向 Windows 10/11 x64，完整安装包增加“安装独立 WebView2 运行环境”复选框。首次默认不勾选，使用系统 WebView2；勾选后使用安装目录 `WebView2Fixed` 中的专用运行时，不替换系统 WebView2。组件包含在完整包中，用户安装时无需下载；不勾选仍会下载完整安装包，但不安装组件文件。macOS 继续使用 WKWebView，中央服务和 Agent 协议不变。

已有用户可以重新运行安装器，选择添加/重装并勾选组件；组件操作不修改配对、设置和历史。升级读取上次选择，应用内被动更新不弹出选项、不强制添加；交互安装取消勾选会移除组件并恢复系统运行时。正常卸载移除专用运行时，更新模式保留它。不要将“独立运行时”当作所有白屏问题的通用修复，显卡、安全软件或用户数据权限问题仍可能需要排查。

客户端在窗口创建前选择运行时。已选组件缺文件、清单无效或窗口构建失败时，显示不依赖 WebView 的原生错误框；日志位于 `%LOCALAPPDATA%\com.centralcodex.localspike\startup.log`，RC 使用其独立 identifier 目录。日志记录运行时选择、版本和启动错误，不记录配对秘密或消息。选中组件损坏时不静默切回系统；应重跑支持该组件的安装器进行修复。

安装器拒绝独立运行时位于 UNC、目录链接或含链接的组件树；更新先暂存新运行时，设置 Windows 10 AppContainer 所需读取/执行权限，再切换目录。组件目录切换失败时尝试恢复旧目录；这不等于整个应用安装具备自动回滚。安装包及故障电脑的真实验收范围见[验证手册](验证与已知限制.md)。

| 现象 | 检查和恢复 |
| --- | --- |
| 网关在线、设备离线 | 检查本机 Agent 是否随桌面启动、配对授权及 `/ws/agent`；不要把中央目录当成本机结果 |
| 证书或网络错误 | 按固定错误码检查系统时间、证书有效期、主机名、信任链或连接超时；配对、HTTP 和 WSS 已统一 Rustls，保留 TLS 验证 |
| 授权撤销或用户停用 | 显示终态并停止重连；管理员恢复可用身份后重新配对 |
| 提交或执行结果未知 | 先核对历史与实际文件；不以新消息 ID 自动重试修改 |
| `MODEL_CREDENTIAL_EXPIRED` | 转中央端按[模型认证手册](模型认证维护手册.md)处理；原失败任务须用户手动重发 |
| 缺少 `VCRUNTIME140.dll` | 0.2.2 的 Agent 已静态链接 CRT；使用完整 0.2.2 安装包覆盖，故障电脑仍需实测 |
