## 用户流程

客户端读取配置后自动检查一次更新；设置增加“版本更新”，显示当前版本、版本说明、下载进度、错误及重试。发现新版本时，主侧栏与设置导航显示入口。

下载完成并通过签名校验后，用户选择“安装并重启”，再确认安装。正在运行的对话、文件操作、未发送的文字或附件会阻止安装。下载不要求停止当前任务；开始安装前才重新核对中央和本机状态。

中央以设备为单位短暂进入维护状态，拒绝新请求；桌面程序等待 Local Agent 停止，再交给系统安装器。安装期间禁止正常关闭窗口、修改账号或配置。Windows 安装器接管进程退出和重启，Mac 更新应用后重启。能被客户端捕获的安装失败会尝试恢复旧 Local Agent；安装器已接管后失败，可能需要重新打开旧客户端或用安装包修复，不能承诺自动回滚。

## 架构与协议

- 更新属于桌面应用自身生命周期，由原生 Tauri 命令处理，与启动、停止 Local Agent 一致；未增加模型工具，未让中央执行客户端文件操作。
- `desktop_update_check/download/install` 是三个原生命令。浏览器只接收版本、说明、进度和状态，不接收 bearer、私钥、下载地址或安装器路径。
- 原生请求使用既有配对 CA 与设备凭据，只允许同一中央 HTTPS 源及 `/client-updates/files/`，禁止代理和 HTTP 重定向。下载最大 512 MiB，超时 10 分钟。
- 更新包使用 minisign 签名；校验失败绝不安装。公钥固化在 Tauri 配置中。
- `GET/HEAD /client-updates/latest.json` 与 `/client-updates/files/<filename>` 仅允许已绑定设备的 bearer。中央只提供清单登记的文件，拒绝任意路径和符号链接。
- `POST /client-updates/prepare` 检查当前设备的对话、请求和工具执行，忙碌返回 409，否则建立 60 秒维护租约；其他设备不受影响。
- `POST /client-updates/release` 需匹配内存中的租约 UUID。重启后调用 `/resume`，用已安装版本匹配预期版本释放租约。异常退出后租约最多 60 秒到期。
- 重启恢复文件 `client-update-attempt-v1.json` 仅保存中央地址、预期版本，不保存 bearer 或租约。已有配对、设置及中央历史存储位置不变。

## 构建与发布

在 `spikes/local-dev/`：

```powershell
npm run package:desktop -- --updater
# 后续版本示例：源码及版本说明需先准备好
npm run package:desktop -- --updater --release-version 0.2.1
```

签名器优先读取 `TAURI_SIGNING_PRIVATE_KEY`，或使用本机忽略目录 `secrets/updater.key`。本次私钥只留在 Windows，没有上传中央 Mac；应单独安全备份，丢失后不能继续给已安装客户端发布同一密钥链的更新。不要将私钥、构建日志或运行数据加入 Git。

Mac 在原生工程执行 `npm run package:desktop` 生成 `.app` 和 DMG，将 `.app` 压缩为 `.app.tar.gz`，取回 Windows 后本地签名。DMG 用于首次安装，自动更新使用签名后的 `.app.tar.gz`。更新签名不等于 Windows Authenticode 或 Apple Developer ID 公证；本次 Windows 未做 OS 代码签名，Mac 为 ad-hoc 签名。

`scripts/publish-client-release.mjs` 校验每个平台的签名，再输出不可变版本文件、SHA-256 清单及 `latest.json`。示例：

```text
node scripts/publish-client-release.mjs --version 0.2.1 --notes-file notes.txt --windows <installer.exe> --macos-arm64 <client.app.tar.gz> --out <new-staging-directory>
```

源文件旁需有对应 `.sig`。本工具只生成可审阅目录，不上传或切换正式服务。
