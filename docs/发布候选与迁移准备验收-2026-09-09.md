# 发布候选与迁移准备验收

本批原范围为双平台候选安装包、原生验收和迁移准备，不包含正式切换。方向调整前，Windows mTLS 候选包验收完成，Mac 原生 Keychain 验收未完成。

2026-09-09 用户已确认改为 HTTPS/WSS、一次性配对码和可撤销设备令牌，**旧 Mac Keychain / mTLS 待验项由新方向取代**，不再以现场操作 Keychain 作为当前下一步。默认切换此前被自动审批拒绝，用户现已明确批准；新方案仍待最终入口集成、真实 4529、Mac 原生和实际新 UI 验收。下文保留旧候选包的历史证据，不能用于宣称新认证方案或第五批全部完成。当前进展见[简化设备认证实施与验收](简化设备认证实施与验收-2026-09-09.md)。

## 旧 mTLS 候选包已验证结果

- Windows x64 RC1/RC2 release NSIS 安装包生成，独立应用标识 `com.centralcodex.harnessqa.rc20260909`、产品 `远舟 RC 20260909`、主程序 `yuan-zhou-rc`，包含 Local Agent。
- Windows RC1 安装、RC1→RC2 升级、RC2→RC1 二进制回退均返回 0，两份配置字节保持，原设备凭据及真实模型历史可恢复。
- 真实 4529 上验证客户端 PowerShell 写入/读取随机 marker，长命令跨原证书到期完成，Agent 自动续期且设备不掉线；中央模型仅通过 Agent 读取未放入提示词的 marker 并形成可恢复历史。
- 重新配对生成新设备后，旧设备对话明确返回 `REMOTE_WORKSPACE_CHANGED`；UI 保持网关/设备在线并给出中文恢复提示，新对话真实模型读取通过。
- 正常窗口关闭后 RC 主程序和 Agent 均退出。部分 UI 激活/快捷键调用未关闭窗口，改用核验 PID 的 `CloseMainWindow()` 正常退出并检查进程；不将发出快捷键本身当作退出成功。
- RC 卸载返回 0、主程序及 Agent 移除、配置保留；随后显式注销 RC 原生会话、清除独立 Vault 条目并恢复配置。工作区和验收证据保留。
- Mac arm64 RC1/RC2 `.app`/DMG 构建通过；前端检查、Rust fmt/desktop check、Agent 19 项和证书 2 项测试通过。RC1 搬迁至独立 `rc-installed` 后，Mach-O 架构及 ad-hoc 签名完整性校验通过。
- 迁移离线预检和合成备份恢复 24 项通过，详见[迁移预检与回退演练](迁移预检与回退演练-2026-09-09.md)。尚未实现真实共享原生历史导入，也没有确认正式账号、设备的归属映射。

## 旧 Mac 未完成项与方向调整

旧方案中，SSH 内的原生 helper 无法写入 Keychain，连非秘密探针也失败；同用户 GUI 会话切换亦被系统拒绝。代理没有解锁、重置钥匙串或调整访问权限。失败准备记录已恢复，未写入 RC 应用凭据/配置。后续现场检查结果见本节末尾，不能把它当作新方案的原生验证。

当时剩余配对、桌面与 Agent 跨进程 Keychain、mTLS 续期等验收未完成；这些旧认证项现已停止作为当前验收目标。启动/正常退出、升级和重新配对后的历史边界仍需用新方案最终候选包验证。不能以编译成功替代运行结果，也不把借用中央 Mac 的同机测试称为异机验收。

旧中央 RC 使用 `p5-rc-security`、`live-data/rc-workers` 和 `qa-rc-control-state.json`；方向调整前记录的 4529 网关 PID 为 904，Windows 临时 bootstrap 当时为 Mac 重试保留。新验收开始前必须重新核对这些进程和临时凭据，最终按实际使用范围清理，不能据此段认定它们现在仍在运行或仍存在。失败 Mac 准备记录为 `rc-native-macos-1/record.json`。本批旧验收没有更新正式 4510。

## 交付与证据

安装包和 SHA256SUMS 位于 `spikes/local-dev/target/rc-delivery/`。Windows 无发布签名，Mac 为 ad-hoc、未公证，属于隔离验收候选包。RC2 打包清理了旧 Mac DMG 输出目录，最终交付 RC2 DMG；搬迁后的 RC1 `.app` 仍在中央 QA 安装目录供后续升级比较。

机器可读汇总为 `spikes/local-dev/harness/verification/p5-release-candidate-qa.json`，其中列出安装包哈希和 Windows 各阶段证据。打包命令及隔离约束见[发布候选隔离打包说明](发布候选隔离打包说明-2026-09-09.md)。本批未提交 Git、未变更原项目或 stash。

旧方案现场检查记录：用户曾确认钥匙串已解锁，但 SSH 内原生非秘密写入仍失败。系统 `security` 同类探针明确返回 `User interaction is not allowed`；UID 501、默认钥匙串为 operator 的 login.keychain-db。该证据不能归结为用户未解锁；之后用户选择了新的设备令牌方案，因此不再要求继续执行旧 helper 的 Keychain 现场探针。
